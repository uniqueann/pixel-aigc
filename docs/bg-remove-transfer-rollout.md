# 智能抠图大图传输上线与验收

## 链路与输出约定

- 浏览器按预计编码后的请求体判断传输方式：不超过 3.5 MiB 时内联；超过时原文件直传 R2，接口只带 `sourceImageKey`。已有对象键直接复用。单张原图仍限制 20 MiB，桌面 24 MP、移动端 12 MP；服务端统一限制 24 MP。
- 服务端根据真实字节校验格式、完整解码和静态图片，恢复 EXIF 方向。适配后的工作副本仅用于腾讯识别透明度，最终商品 RGB 来自解码后的原图。
- 腾讯输入仅使用 PNG/JPEG，工作尺寸不超过 7680×4320，最小 32×32，文件不超过 9,500,000 字节。始终保持 EXIF 校正后的商品朝向；超尺寸等比缩小，不为满足高度限制将商品横转。3200×5035 的竖图使用 2746×4320 的直立副本。短边不足 32 像素只为识别副本补白。WebP、透明输入及其他需适配的输入转为铺白 JPEG。
- 体积适配先尝试 JPEG 质量 95、90、85、80、75、70，仍超限时按 85% 缩小副本。原图不缩小、不覆盖。合规、不需适配的对象输入直接复用原对象。
- 默认向腾讯 `GoodsMatting` 提交一小时有效的 R2 签名源地址，设置 `center-layout=0`，使用根路径 GET。查询参数包含在腾讯请求签名中，统一编码一次。新链路不写腾讯 COS 原图和结果临时对象，也不自动重复付费处理请求。
- 腾讯返回必须是同工作尺寸的静态透明 PNG。提取 Alpha 后去掉补白、线性插值到原尺寸，并与原图已有透明度相乘；不硬阈值化、不额外模糊。最终 PNG 保存原尺寸和商品原图颜色；完全透明处的 RGB 清零以减少文件体积，边缘精修恢复商品时仍读取原文件。
- 结果不超过 3.5 MiB 时直接返回 PNG；更大结果存入 `temporary/bg-remove-results/{userId}/{requestId}.png`，返回对象键、PNG MIME、字节数和十五分钟签名地址，浏览器直读 R2。腾讯响应和最终 PNG 均设 128 MiB 安全上限。

腾讯能力依据：[商品抠图 API](https://cloud.tencent.com/document/product/460/79735)、[使用限制](https://cloud.tencent.com/document/product/460/36620)。恢复原尺寸不会增加蒙版识别细节，细线、毛发、镂空和半透明边缘需要真实素材验收。

## 接口兼容与重试

`POST /api/bg-remove` 支持以下两种互斥输入，均可附带 `clientTimingMs: { prepare, upload }`：

```json
{ "mimeType": "image/jpeg", "dataBase64": "图片编码" }
```

```json
{ "sourceImageKey": "temporary/task-inputs/当前用户/对象" }
```

大结果响应：

```json
{
  "objectKey": "temporary/bg-remove-results/当前用户/请求.png",
  "url": "R2 签名下载地址",
  "mimeType": "image/png",
  "bytes": 5000000,
  "expiresAt": 1900000000000
}
```

- 对象只能属于当前账号，不接受客户端传入的任意外部 URL。权限和检测限流沿用原实现：每小时 60 次、最多三个并发，不引入积分扣除。
- 队列原图键和结果描述在当前账号的内存会话中保留，刷新后清空。处理失败重试复用原图；大结果下载失败保留结果描述，下一次只重试下载；签名失效重新签发一次。结果确认为 404 时重新处理，原图确认为已清理时重新上传一次。
- 下载不退回 `/api/objects` 图片代理。换背景和边缘精修复用已取得的透明 Blob；本地合成失败也保留它。透明原尺寸下载直接复用 PNG Blob，白底和纯色继续本地合成 JPEG。
- 取消或离开页面会中止上传、处理接口请求和结果下载并停止排队。已经开始的腾讯处理可能继续，取消不承诺撤销供应商操作。
- 上传最多 120 秒，浏览器处理接口最多 115 秒，下载最多 60 秒。腾讯等待和响应读取合计最多 70 秒；服务端处理截止为请求开始后 100 秒，结果保存截止为 105 秒，留出函数 120 秒限制的余量。

## 迁移与发布

1. 先执行 `20261001120433_bg_remove_transfer_retention.sql`。它只将 `bg-remove` 记录纳入七天保留列表，不修改表结构、限流、积分或权限。其他同步检测记录继续按两小时清理。`content-up` 已于 2026-10-01 执行并核验函数定义和调用权限；本地文件从 PR #62 的 `20261001104554` 版本重命名为线上实际登记版本，SQL 内容相同，已迁移的环境不要重复执行。
2. 复核 R2 私有桶对正式站点允许 `GET`、`HEAD`、`PUT` 和请求头 `Content-Type`，以及 `temporary/` 七天生命周期。预览域名需单独加入允许来源。
3. 腾讯原有四项环境配置继续使用；下载时处理还需要 `cos:GetObject` 与 `ci:CreateGoodsMattingJob` 权限。旧上传路径可用不代表新 GET 路径权限齐全。
4. 发布服务端兼容改造，再发布前端，按下方清单完成真实验收。浏览器直传成功不能证明腾讯运行环境能读取签名地址，必须完成真实抠图确认。
5. 若新链路需要回退，恢复旧服务端和前端；旧 COS 上传实现仍保留在代码中。七天保留迁移兼容旧版，可保留。旧版大图仍受原有请求和响应体限制。

## 耗时观测

`aigc.sync_requests` 记录 `route='bg-remove'`、输入 `transport`、原图/结果字节数、状态和错误码。`stage_ms` 记录 `clientPrepare`、`clientUpload`、`objectRead`、`imageValidate`、`inputPrepare`、`providerInputWrite`、`providerTtfb`、`providerDownload`、`restoreAlpha`、`objectWrite`；未发生的阶段不填充。

`providerTtfb` 包含腾讯内部拉图与识别等待，不能独立解释为模型运行时间。`restoreAlpha` 包含原尺寸蒙版恢复和 PNG 编码。输入准备结构化日志补充原图/工作图/有效内容尺寸、`orientationPolicy='upright'`、缩放比例与原对象复用情况；成功日志补充供应商输入字节数、源图 MIME 和输入/结果传输方式，不记录签名地址、凭证或供应商原始错误正文。

浏览器 `bg-remove-client` 记录结果获取时间，`bg-remove-compose` 记录本地合成时间。服务端记录不包含浏览器下载和背景合成，完整等待需结合网络面板比较；按相同素材与输入大小分组，观察成功率、中位数和 P95。

## 真实验收清单

- 小 JPG、PNG；约 5 MB 的 3200×5035 竖图；WebP；超过 10 MB 的原文件；EXIF 旋转图；已有透明区域的图片。
- 大图 `/api/bg-remove` 请求只带对象键，腾讯日志 `inputTransport='url'`。超过 3.5 MiB 的 PNG 经 R2 下载成功，返回文件扩展名、MIME 和真实格式都是 PNG。
- 商品内部放大对比原图，RGB 和清晰度保持；细线、毛发、孔洞、半透明区域无错位或明显硬边。输出宽高与浏览器解码后的原图一致。
- PR #62 曾将高竖图横转后识别，存在模型误删部件的风险。质量修复后需刷新页面、重新选择耳机原图再生成，避免复用旧结果；逐项检查头梁、连接杆、左右耳罩和线缆是否完整。直立输入的代码验证不能替代真实商品素材验收。
- 处理失败后重试不重复上传，下载失败后重试不再次调用腾讯；签名刷新可恢复；对象被清理后可重新上传或处理。
- 同时提交多图，单张失败不阻断其他项；上传、等待和下载阶段取消；切换账号后不复用其他账号的队列与对象。
- 白底、纯色、透明输出、边缘精修、卡片下载和 ZIP 正常；换背景不增加腾讯调用次数。
- 同一组大小图各重复至少三次，与旧版对比分阶段耗时及成功率。当前仓库的自动测试和本地性能测试不能替代腾讯读取真实 R2 地址的验收。

## 本地性能验证

2026-10-01 在当前开发机上使用确定性纹理 JPEG 与模拟透明蒙版测试，仅测本地图片适配和恢复，不含 R2、腾讯等待和浏览器下载。以下是 PR #62 横向工作副本策略的历史性能样例；直立策略的实际耗时和质量需另行真实验收：

| 场景 | 结果 |
| --- | --- |
| 3200×5035 原图，10.85 MiB | 识别副本 5035×3200、8.35 MiB；原尺寸 PNG 51.23 MiB；副本准备 556 ms，蒙版恢复和编码 746 ms；进程峰值 RSS 446.4 MiB |
| 三张 3000×8000、各 15.02 MiB 并行 | 三张均输出原尺寸；适配与恢复总计 2744 ms；进程峰值 RSS 1342.9 MiB |

蒙版设为全图半透明，属于大 PNG 的体积和内存压力样例。实际完全透明的背景 RGB 会清零，便于 PNG 压缩。部署验收需对照函数配置检查三任务并行的内存余量。

开发机具备腾讯配置，未具备 R2 完整配置，因此本地没有完成腾讯读取真实 R2 签名地址的供应商联调。PR #62 合并后用户反馈六张真实素材的传输、透明 PNG、原图尺寸、三张并发和 ZIP 均通过；3200×5035 耳机图存在商品部件被抠掉的问题，直立副本修复后的质量仍需用同一原图和结果对比验收。
