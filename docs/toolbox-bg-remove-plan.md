# 工具箱 · 智能抠图 — 开发规划

> 当前代码：P1 与边缘精修已落地。真实抠图不走 `Capability.BgRemove` 任务。四项 `TENCENT_COS_*` 齐全时，`POST /api/bg-remove` 调用数据万象 GoodsMatting；缺配置时入口显示即将上线。主体检测仍见 [`toolbox-subject-detect-todo.md`](./toolbox-subject-detect-todo.md)。

## 1. 目标

批量去掉商品图背景，再铺上透明、白底或指定纯色。队列、限额、预览和 ZIP 沿用加水印、转比例已经落地的骨架。真实抠图走腾讯云数据万象，模拟模式才使用 `Capability.BgRemove` 假任务。

边缘精修把单张透明结果带到图片工作站的消除蒙版，不在抠图页再做一套画笔。这一步已经落地。

## 2. 第一期行为

| 项 | 约定 |
|----|------|
| 输出背景 | 透明、白底 `#ffffff`、或一个纯色。记住上次选择 |
| 格式 | 透明为 PNG。白底和纯色为 JPEG，质量 `0.92` |
| 尺寸 | 与原图宽高一致，不在这一步改比例 |
| 批量 | 复用 `shared/inspect`：最多 20 张，JPG/PNG/WebP，ZIP 上限 200MB |
| 并发 | 同时最多 3 个抠图任务。单张失败只标记该张，可单张重试或重试全部失败项 |
| 预览 | 当前图的降采样结果。未处理时显示原图 |
| 真实抠图 | 非模拟模式先读 `GET /api/capabilities`。`bgRemove` 为 true 时走 `POST /api/bg-remove`；为 false 时页面显示即将上线，不能开始处理。模拟模式不调用腾讯云 |

抠图结果先得到透明底，再在本机铺白底或纯色。这样换背景色不必重跑模型。换背景色后，已有结果用新的底色重新合成，不重新请求抠图。

## 3. 分期

| 阶段 | 内容 | 状态 |
|------|------|------|
| P1 | `BgRemoveTool`、三种背景、记住上次选择、本机批量、预览、逐张和 ZIP 下载。模拟任务返回可合成的透明结果 | 已落地 |
| P2 | 真实抠图走 `POST /api/bg-remove`，数据万象 GoodsMatting，不经过 `/api/tasks`。结果 `fileid` 使用绝对路径，再按返回的对象 key 读取 | 已落地，依赖四项 `TENCENT_COS_*` |
| P3 | 单张透明结果带到工作站蒙版做边缘精修，见 §7 | 已落地 |

P1 不做法布画笔，也不做主体检测。

## 6. 第一期实现约定

第一期只做批量抠图、三种背景、记住上次选择、预览和 ZIP。边缘精修仍是 P3。

**一张图存两份结果**

- `matte`：抠图返回的透明 PNG，宽高等于解码后的原图
- `output`：按当前背景合成后的下载文件
- 换背景只重写 `output`。已有 `matte` 的图片不再提交任务

**处理顺序**

1. 本机 `inspectImage` 入队，解码用 `imageOrientation: 'from-image'`
2. 没有 `matte` 的图片才上传并调用 `Capability.BgRemove`
3. 同时最多 3 个任务。返回图解码后的宽高必须等于原图，否则这张失败
4. 透明背景时 `output` 就是 `matte`。白底或纯色在本机把颜色铺在透明图下面，再编码

**背景**

- 默认白底 `#ffffff`
- 透明导出 PNG。白底和纯色导出 JPEG，质量 `0.92`
- 纯色只接受 `#rrggbb`
- 上次选择写入 IndexedDB `pixel-aigc-bg-remove-prefs`，按 `userId ?? 'local'` 分开。只存背景，不存队列

**预览和下载**

- 已有 `matte` 时，预览按当前背景合成，最长边 800px
- 还没有 `matte` 时显示原图
- 文件名复用去重规则，后缀 `_cutout`
- 卡片下载 `output`。ZIP 只打包已成功的 `output`

**模拟与真实调用**

- `VITE_GENERATION_MODE=mock` 且未启用云同步时，不调用腾讯云。假任务返回一张与原图同尺寸、带透明通道的 PNG
- 其余情况由 `GET /api/capabilities` 决定。配置齐全时 `POST /api/bg-remove`，请求体为 `mimeType` 与 `dataBase64`，响应为 PNG，单张不超过 20 MB
- 服务端在 `fileid` 前补上 `/`，避免结果被写到原图目录的下一层。读取时使用数据万象返回的对象 key

**第一期范围**

- 不改比例，不放大
- 第一期不做画笔。边缘精修已按 §7 落地，主体检测不在抠图里做
- 换背景不重新上传、不重新排队

## 7. 边缘精修开发步骤

边缘精修改的是这张图的透明底，不是再跑一次抠图，也不是消除/重绘那种生成新图。画笔复用工作站现有的 `MaskPaintCanvas` 和笔刷工具条，抠图页不再做一套画笔。

消除和重绘的「生成」会交出一张不透明图，不能再拿来换底色。这次交接打开的是同一块蒙版画布，主按钮是「完成精修」，不提交 `inpaint`。

**步骤**

1. 只有已经有透明结果的队列卡片显示「修边缘」。失败或还没抠完的图没有这个入口。
2. 离开抠图页时，队列不能丢。把当前队列放在内存模块里，路由切换后还能拿回来。刷新页面仍然清空，不写入 IndexedDB。
3. 交接内容是这一张的原图、透明底、宽高和队列项 id。打开 `/image-workstation/remove`。
4. 工作站看到这是抠图精修时，载入原图，底下用现有蒙版画笔。页脚主按钮改为「完成精修」。用户改去别的工具时，先丢掉这次精修交接，避免和消除的生成任务混在一起。
5. 画笔把涂到的像素变成透明，用来擦掉残留背景。橡皮擦把这些像素从原图恢复回来，用来补回被抠掉的商品边缘。未涂抹的地方保持原来的透明底。
6. 完成精修后导出一张同尺寸的透明 PNG，写回该队列项的 `matte`，再按当前背景重合成 `output`。不上传，不提交抠图任务。
7. 取消精修则透明底不变，直接回到 `/toolbox/bg-remove`。

**测试**

- 没有透明结果时不出现「修边缘」
- 画笔像素变透明，橡皮擦从原图恢复，其余像素不变，输出宽高不变
- 写回后换背景仍用新的透明底，且不再请求抠图
- 取消后原透明底还在
- 从抠图页跳到工作站再回来，队列还在；刷新后队列清空
