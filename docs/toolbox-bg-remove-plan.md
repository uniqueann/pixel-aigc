# 工具箱 · 智能抠图 — 开发规划

> 转比例主体检测先停在 [`toolbox-subject-detect-todo.md`](./toolbox-subject-detect-todo.md)。下一步开发工具箱里仍是占位的智能抠图（`/toolbox/bg-remove`）。

## 1. 目标

批量去掉商品图背景，再铺上透明、白底或指定纯色。队列、限额、预览和 ZIP 沿用加水印、转比例已经落地的骨架。抠图能力使用已有的 `Capability.BgRemove`，不在工具箱里另接一套模型。

边缘精修放到后一阶段：把单张结果带到图片工作站的消除/重绘蒙版，不在第一期做画笔。

## 2. 第一期行为

| 项 | 约定 |
|----|------|
| 输出背景 | 透明、白底 `#ffffff`、或一个纯色。记住上次选择 |
| 格式 | 透明为 PNG。白底和纯色为 JPEG，质量 `0.92` |
| 尺寸 | 与原图宽高一致，不在这一步改比例 |
| 批量 | 复用 `shared/inspect`：最多 20 张，JPG/PNG/WebP，ZIP 上限 200MB |
| 并发 | 同时最多 3 个抠图任务。单张失败只标记该张，可单张重试或重试全部失败项 |
| 预览 | 当前图的降采样结果。未处理时显示原图 |
| 模型未接入 | 与扩图相同：模拟模式可走完流程；账号下的真实模式仍由现有接口拒绝未接入的生成能力 |

抠图结果先得到透明底，再在本机铺白底或纯色。这样换背景色不必重跑模型。换背景色后，已有结果用新的底色重新合成，不重新请求抠图。

## 3. 分期

| 阶段 | 内容 | 依赖 |
|------|------|------|
| P1 | `BgRemoveTool`、三种背景、记住上次选择、本机批量、预览、逐张和 ZIP 下载。模拟任务返回可合成的透明结果 | 无新模型 |
| P2 | 真实抠图接口接入 `Capability.BgRemove` | 后端 Provider |
| P3 | 单张结果带到工作站蒙版做边缘精修 | P1 的结果图 |

P1 不做法布画笔，也不做主体检测。

## 5. 测试

- 透明输出为 PNG，白底和纯色输出为 JPEG，宽高等于原图
- 换背景色时用已有透明结果重合成，不增加任务次数
- 并发不超过 3，单张失败不阻断其余图片
- 刷新后恢复上次的背景选择

## 6. 第一期实现约定

第一期只做批量抠图、三种背景、记住上次选择、预览和 ZIP。边缘精修仍是 P3。

**一张图存两份结果**

- `matte`：抠图返回的透明 PNG，宽高等于解码后的原图
- `output`：按当前背景合成后的下载文件
- 换背景只重写 `output`。已有 `matte` 的图片不再提交任务

**处理顺序**

1. 本机 `inspectImage` 入队，解码用 `imageOrientation: 'from-image'`
2. 没有 `matte` 的图片才上传并调用 `Capability.BgRemove`
3. 同时最多 3 个任务。返回图解码后的宽高必须等于原图，否则这张失败
4. 透明背景时 `output` 就是 `matte`。白底或纯色在本机把颜色铺在透明图下面，再编码

**背景**

- 默认白底 `#ffffff`
- 透明导出 PNG。白底和纯色导出 JPEG，质量 `0.92`
- 纯色只接受 `#rrggbb`
- 上次选择写入 IndexedDB `pixel-aigc-bg-remove-prefs`，按 `userId ?? 'local'` 分开。只存背景，不存队列

**预览和下载**

- 已有 `matte` 时，预览按当前背景合成，最长边 800px
- 还没有 `matte` 时显示原图
- 文件名复用去重规则，后缀 `_cutout`
- 卡片下载 `output`。ZIP 只打包已成功的 `output`

**模拟**

- `bg_remove` 的模拟结果是一张与原图同尺寸、带透明通道的 PNG
- 账号开启且未走模拟时，现有任务接口仍会拒绝。这张图标记失败，失败原因沿用接口返回的文案

**不做**

- 不改比例，不放大
- 不在第一期做边缘精修和主体检测
- 换背景不重新上传、不重新排队
