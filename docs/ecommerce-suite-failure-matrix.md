# 电商套图故障矩阵与验收编号

基线：`55e6040`；阶段一仅验证结构、模板和局部不变量。[合同代码](../shared/ecommerce-suite.ts)、[合同测试](../shared/ecommerce-suite.test.ts)、[样例与证据](verification/ecommerce-suite/phase-one/README.md)、[数据库契约](ecommerce-suite-database-contract.md)共同定义后续验收。

## 1. 已有可执行合同检查

以下是纯本地 Schema 断言，不是登录、RLS、生成、扣费或恢复服务的实现证据。最近执行结果见[本地检查报告](verification/ecommerce-suite/phase-one/local-checks.json)。

| 编号 | 输入／故障 | 合同断言 |
| --- | --- | --- |
| EC-C01 | 写请求夹带账号、环境、积分、任务状态或图片 URL | 严格 Schema 拒绝，配置内部同样拒绝 |
| EC-C02 | 槽位 ID、key、order 重复或不足七项 | 拒绝保存，避免错误归属与重复派发计划 |
| EC-C03 | Amazon 主图挪到非零序号或关闭 | 换序号合法，关闭主图非法 |
| EC-C04 | Amazon 缺美国站、通用模板伪带站点 | 拒绝不对应的平台／站点 |
| EC-C05 | 标签去空白后重复、尺寸负数／NaN／单位错误／同对象同方向冲突 | 保持语义，整体与部件分别记录，不把长改写成高 |
| EC-C06 | 版本引用未确认、缺失或文字型数值事实 | 成品快照拒绝；允许项目保存待确认事实 |
| EC-C07 | 标注线越界或退化、临时空文字 | 拒绝坏坐标；空文字只允许编辑草稿 |
| EC-C08 | 当前指针包含其他槽位或重复头记录 | 拒绝不覆盖当前项目全部槽位的读模型 |
| EC-C09 | 候选数量与单价／明细／总额不一致、重复报价槽位 | 拒绝不一致报价，不以选用一张代替成功候选张数 |
| EC-C10 | 主图或尺寸直接收费重造、复用步骤虚报费用、报价有效期漂移 | 拒绝不符合首期策略的报价 |
| EC-C11 | 持久资产保存临时路径、签名地址、穿越键、超限或非静态图片上传类型 | 拒绝持久身份与上传参数 |
| EC-C12 | 本地复用伪造模型／收费来源、回填无工具、同步结果序号不为零 | 拒绝不完整或伪造的版本来源 |
| EC-C13 | Amazon 导出 WebP、JPEG 透明背景 | 拒绝；通用 WebP 合法 |
| EC-C14 | 模板缺槽位、推荐项自动声明性能、未经绑定的入口声明套图来源 | 三模板生成合法配置，推荐仅风格；阶段二通用任务入口拒绝客户端声明的套图来源，仅已验证操作可创建，阶段三父批次仅作只读聚合 |
| EC-C15 | 操作停止已绑定任务、串原请求号、复用步骤夹带原任务 | 拒绝改写原任务身份或在复用步骤引入收费，父批次拒绝独立计费状态 |

## 2. 后续必须验证的运行故障

下列项目在阶段一均为**待实现／待运行验证**；合同测试不能替代这些证据。每个案例记录原请求、原任务、环境、发生次数、实际费用、结果资产及页面行为。

阶段二已完成部分本地运行验证，见[阶段二证据](verification/ecommerce-suite/phase-two/README.md)。真实供应商、R2 和九个商品样本仍待补齐，不能将本机 Mock 或浏览器 HTTP 合成数据记为目标环境通过。

| 编号 | 场景 | 必须证明 | 阶段／方法 |
| --- | --- | --- | --- |
| EC-R01 | 创建项目连点／响应丢失，同键异参 | 同键只有一个项目，找回不创建，同键异参 409 | 二，HTTP＋PostgreSQL |
| EC-R02 | 跨账号／环境伪造项目、槽位、资产、版本、报价与会话 ID | API、RLS、复合关联、对象访问同时拒绝 | 二／三／四，实际应用角色 |
| EC-R03 | 配置／草稿／当前指针修订冲突 | 保留本机副本，不串修订，不静默覆盖 | 二／四，浏览器＋HTTP |
| EC-R04 | 临时上传未完成、真实 MIME 不符、超大像素 | 不登记 ready；收费生成不读取未核验对象 | 二，HTTP＋实际解码 |
| EC-R05 | URL 过期、对象暂不可读或实际被删 | 续签与缺失分开，下载不重做生成 | 二，受控 R2／浏览器 |
| EC-R06 | 接受批次重复／并发，不同请求抢同一报价 | 同报价只接受一次，单项目活动批次唯一 | 三，PostgreSQL 并发 |
| EC-R07 | 最后积分被其他工具争用 | 原账本不透支，原任务创建和绑定一起回滚 | 三，真实账本事务 |
| EC-R08 | 原任务创建成功但响应丢失 | 原稳定请求找到原任务，不再次预扣或提交 | 三，HTTP 故障注入 |
| EC-R09 | 两个执行器领取，旧租约晚到 | 仅有效令牌能绑定／应用，零重复执行 | 三，PostgreSQL 并发 |
| EC-R10 | 领取中停止，停止后旧执行器继续 | 未建项停止，已建项正常结算，不能越过隔离令牌 | 三，锁竞争注入 |
| EC-R11 | 上游是否接收不明，原任务后来过期／清理 | 保持 confirming／原终态，404 不授权新尝试 | 三，原任务恢复集成 |
| EC-R12 | 关页时仍有 waiting 项 | 不依赖浏览器，已接受计划继续首次派发并收口 | 三，目标环境关浏览器 |
| EC-R13 | 余额不足、目录变价／下线、限流、30 分钟截止 | 阻塞／停止正确，再确认只含未执行或所选失败项 | 三，HTTP＋维护器 |
| EC-R14 | 七槽位两个失败、单槽位四候选两个成功 | 两种分母分别显示，保留成功项，按原账本结算 | 三，真实／可控供应商 |
| EC-R15 | 超时退款后晚到、供应商重复回调 | 沿用原收口，不重复追扣或覆盖已选版本 | 三，原服务＋账本 |
| EC-R16 | 成功后对象转存／版本登记失败 | 只修复登记、无第二次生成；孤儿不误删引用 | 二／三，I/O 故障注入 |
| EC-R17 | 切账号、旧查询／保存／结果晚到 | 原账号状态不能进入新会话 | 二／四，浏览器＋HTTP |
| EC-R18 | 本机配额不足／云保存失败／关闭页面 | 如实显示备份完整性，恢复包导入不重放收费请求 | 二／四，浏览器／恢复 ZIP |
| EC-R19 | 尺寸和语言后来改动、回退旧版本 | 旧版只读自身事实与图层快照，输出不漂移 | 四，浏览器＋文件比对 |
| EC-R20 | 工作站重复回填、来源已更新、项目删除／会话过期 | 同结果同版本，过时仅候选，原工具费用仅一次 | 四，HTTP＋PostgreSQL |
| EC-R21 | 已合成底图回填、画板比例变化、蒙版输入 | 不叠两份文字，显式确认重排，不串工作站草稿 | 四，浏览器 |
| EC-R22 | 主图底图带字／透明白色商品无可靠蒙版 | 叠加锁与内容预检分开，未知不能通过 | 五，真实商品人工核对 |
| EC-R23 | 导出时切版本，字体未加载，单图编码／读取失败 | 冻结清单，等待字体，仅重试对应文件 | 四／五，实际文件检查 |
| EC-R24 | 4K 多图、200 MB 超限、取消、ZIP 重名 | 内存有界，正确扩展名／清单／释放，无收费生成 | 五，短屏／窄屏＋实际 ZIP |
| EC-R25 | 删除／恢复／到期清理时存在原任务或共享引用 | 未派发停止、原任务结算、账本与引用对象保留 | 五，PostgreSQL＋对象存储 |

## 3. 真实商品样本门槛

[sample-plan.json](verification/ecommerce-suite/phase-one/sample-plan.json) 定义 F01～F03、K01～K03、S01～S03 九个商品，三个子类各三个。当前 `receivedCount = 0`、全部 `awaiting_input`；无真实图片、SKU 或已验证规格。

每个样本收集有使用权限的主体实拍、可核对规格、适用的细节实拍，并记录授权来源、输入资产 ID、模型与原任务、人工外观核对、实际导出文件和账本结果。仅当图片与规格可用且证据完整才把单样本改为 ready／验收通过；两者状态不能混用。

附件沙发由 HTML 图形绘制，不能计入九个真实样本；合同 fixture 的数值和模拟模型费用也不能作为真实产品事实或价格。

## 4. 阶段三本地覆盖

[阶段三证据](verification/ecommerce-suite/phase-three/README.md)覆盖 EC-R06～R10、R13、R14、R16 的独立 PostgreSQL／模拟供应商场景，补充实际角色越权、父子计数与最后积分争用。EC-R12 已证明本机连续维护不依赖浏览器，但目标环境定时调用、关页持续运行仍待验证。EC-R08 的真实 HTTP 响应丢失、EC-R11／R15 的供应商未知提交与晚到账单仍需目标环境证据，不能将本地模拟收口视为通过。

后台登记统一只保存候选，无法观察本机未同步草稿时不会切换当前成品；旧租约在转存后的最终写入再次被拒绝。图层／桥接／导出和清理的其余编号仍保持后续阶段范围。
