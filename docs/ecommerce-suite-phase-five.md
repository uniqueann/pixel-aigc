# 电商套图阶段五：平台预检、批量导出与受限清理

基线为 `main / 6cac7f9`，阶段四 PR #197 与函数包修复 PR #198 已合并；开发分支 `feat/ecommerce-suite-phase-five`。预检、成品输出与到期清理按开发计划依次实现。本阶段代码与本地证据可审查，发布验收仍未完成，真实商品样本保持 **0/9**。证据见[阶段五验收记录](verification/ecommerce-suite/phase-five/README.md)。

## 1. 平台预检

`POST /api/ecommerce/suites/:id/prechecks` 只读取已有项目、版本和持久资产，冻结所选版本、项目配置、当前指针、输出配置与规则版本，返回 `checkedVersionIds`、逐文件检查、时间及 SHA-256 指纹，不创建任务或账本流水。同槽只能选择一个版本，跨项目、账号、运行环境或回收站来源不可访问。

四类结果为 `pass / warning / unknown / fail`。每项包含规则 ID／版本、依据、方法、修复建议；根报告包含平台／站点、规则复核日期、被检版本和检查时间。确定性失败阻止对应文件，警告／未知需要用户明确核对；部分失败不能阻止其他成功文件导出。

当前规则版本为 `2026-10-17-v1`。旧项目保留原规则身份并提示复核，可在商品资料中显式更新规则版本；不静默改写历史。2026-10-17 已读取 [Amazon 官方图片说明](https://sell.amazon.com/blog/product-photos)，实现最长边 500～10000px、首期 JPEG／PNG，以及图片数量和放大查看建议；要求与推荐分开。2000×2000 JPEG 是产品预设，不声称为平台唯一合法尺寸。

[美国站商品图片要求](https://sellercentral.amazon.com/help/hub/reference/external/G200216080)的具体类目正文需要卖家身份复核。家具家居、厨房餐饮和收纳家纺仅是本产品分组，不视为类目认证；相关项保持 `unknown`。当前资产未保存经过核验的前景蒙版，主图白底及主体占比不能可靠自动测量，保持未知；底图文字、水印、品牌授权、颜色和配件数量同样通过原图对照人工核对。没有调用 OCR、视觉模型或收费检测。

主图按 `kind: main` 锁定叠加层与不透明白底。尺寸图检查本版本确认事实，项目后来修改的规格不能补造旧版本事实。版本渲染器不受当前客户端支持时阻止输出。放大与画板比例变化列为警告，不自动调用收费增强。

## 2. 成品导出

单图和批量使用同一入口。选择槽位、实际像素、JPEG／PNG／通用 WebP、质量及透明策略；Amazon 只提供 JPEG／PNG。保存所选草稿并形成完整版本后执行预检；缺失、活动任务和失败槽位逐项列出，用户可确认只导出成功项。

底图等比完整放入目标画板，不自动裁切商品；图层保持归一化坐标，字号和笔画按原画板宽度缩放。改变比例可能影响标注与商品的相对位置，需通过实际输出预览核对。预览和编码复用阶段四 Canvas、固定字体、换行和越界检查；JPEG 明确铺底，通用 PNG／WebP 可保留透明度，Amazon 主图固定白底。

每次只读取、解码和合成一张图片，完成后释放画板和位图，保留编码后的 Blob。输出预览使用小缩略图，打开大图时才加载实际文件，避免七张 4K 成品同时作为原尺寸预览解码。单画板最多 4000 万像素；沿用共用 ZIP 的 200 MiB 结果总量限制，并将清单计入打包大小。超限提示缩小或拆分，不裁剪历史、不发起生成。

编码后读取实际文件头、重新解码像素、读取字节数并计算 SHA-256，不能以请求选项代替文件证据。文件名含安全化项目名、槽位序号／名称、版本与实际宽高，控制中文名称长度并按稳定序号避免重名。

修改输出设置、项目、当前版本或图层会使旧检查失效；导出处理始终使用冻结快照。下载前再次调用只读预检核对云端指纹，云端配置／指针变化或权限失效时要求重新检查。下载失败只重新读取、编码或打包；重试失败文件复用本次已成功的 Blob。取消不会提交生成或下载半成品。

成品 ZIP 使用 `pixel-suite-export / 1`，含实际图片及 `manifest.json`：平台、规则与输出配置、被检版本、文件元数据／校验值、人工确认及失败／跳过原因。不包含对象键、短期签名、令牌、提示词或可执行任务身份。恢复 ZIP 仍使用独立的 `pixel-suite-recovery` 格式和导入入口，成品包不能用于恢复云端项目权限或任务。

## 3. 回收站与资产寿命

恢复期仍为七天。移入回收站在项目锁内停止未派发项、隔离旧领取令牌；已绑定原任务继续按原规则执行和结算。恢复不重新启动停止的队列，重新生成需要用户重新报价确认。恢复截止以数据库时间为准；界面显示截止时间及超期状态。

新增迁移：[20261017104906_ecommerce_suite_phase_five.sql](../supabase/migrations/20261017104906_ecommerce_suite_phase_five.sql)。项目增加清理隔离／完成标记，资产增加已清理标记，新增两表：

- `suite_object_writes`：在持久对象写入前登记意图，追踪已登记图片及对象成功、资产登记失败时留下的已知孤儿。现有 ready 资产随迁移补入。
- `suite_sync_inputs`：同步原任务只保存输入指纹，故在原预扣事务中补充套图实际输入引用；保留原收费状态与账本，不另建计费状态机。

两表使用账号、运行环境、有效成员 RLS、复合外键和必要索引，撤销 PUBLIC／anon／authenticated 访问。普通角色不能写清理标记、覆盖历史版本或修改原账本。图片服务校验套图输入时锁住来源项目，同步输入绑定也在原创建事务中锁项目，防止清理隔离后产生新引用；普通工具无套图输入时不查询新表。

独立入口 `POST /api/internal/ecommerce-suite-cleanup` 校验既有 `IMAGE_CRON_SECRET` 与运行环境，只在 `ECOMMERCE_SUITE_CLEANUP_ENABLED=true` 时运行；可在入口关闭时维护已到期项目。每轮最多隔离四个到期且批次已收口的项目、删除八个对象，45 秒总预算，单对象删除 10 秒。外部 I/O 均在短事务之外。

清理依次执行：项目超过恢复期且无活动批次／操作租约／确认中项 → 写清理隔离标记，阻止新读写和任务引用 → 领取距最后写入至少 24 小时的对象 → 再检查全部已知引用 → 事务外删除 → 凭领取令牌收尾。原图片任务的实际输入、同步输入及仍有效会话被引用时保留，即使任务已结算也等原记录按原服务留存结束。引用中的对象延后一天再查，删除失败五分钟后可重试，旧领取令牌不能收尾新租约。

清理仅处理当前环境、到期项目自身前缀内的已登记持久对象，不扫描其他产品桶前缀。早于本迁移且既无资产记录也无写入意图的遗留孤儿不能自动发现，应先做只读对象盘点；临时上传仍由既有桶生命周期管理。活动项目中的失败写入不被后台静默删除，随项目到期统一处理。

只有全部已知持久对象清理完成才标记项目完成。删除凭据、版本快照、原任务关联与账本元数据保留用于幂等与费用追溯；图片字节被清理后项目不能恢复。此操作不是账本、原任务或其他产品数据的永久删除接口。

## 4. 发布前验证与回退

本地已覆盖纯逻辑、独立 PostgreSQL 完整迁移链／实际 `aigc_api`、真实本地 HTTP、React 页面、实际 PNG／JPEG／WebP／ZIP。供应商与对象桶为本地替身，测试身份不等于真实 Auth；主动将恢复期限与重试时间置为到期只用于加速检查，不能据此声称真实分钟调度或七天调度已验收。

新增 `ECOMMERCE_SUITE_EXPORT_ENABLED=false`、`ECOMMERCE_SUITE_CLEANUP_ENABLED=false`，入口及既有派发开关继续默认关闭。本轮未应用远端迁移、改动远端环境、配置定时器或提交付费模型。

目标环境依次验收：

1. 只读核对迁移历史、PostgreSQL 版本、实际角色权限及备份；应用阶段二至五迁移后验证跨账号／环境隔离。已复核 [Supabase 数据库升级说明](https://supabase.com/changelog/postgres-15-19-17-11-breaking-changes)，本阶段不修改扩展或连接配置。
2. 用测试账号和真实 R2 验证上传、签名过期后重新读取、历史与恢复包、单图和 ZIP。
3. 在明确积分上限内验证三类各三个真实商品、四工具回填、部分失败与原账本收口；逐项记录模型、实际任务、消费与退款。样本不得用本目录合成商品替代。
4. 验证原图片维护及套图定时器连续运行，关闭页面后继续首次派发与收口；清理使用单独同环境调度，先以可丢弃测试项目演练引用保护、对象失败和截止。
5. 复核目标卖家类目规则、深浅／系统主题、侧栏、窄屏／短屏、字体与 4K 文件，再分别开放入口、派发、导出及清理。

回退先关闭新入口／导出／清理与未执行项派发，保留原任务维护、查询、结算及已保存成品；不要删表、清空账本或删除被引用对象。清理已实际删除的字节不会因关闭开关恢复，首次启用前必须保留测试备份并演练恢复。目标环境尚未执行这些步骤，`phaseFiveExitPassed=false`。
