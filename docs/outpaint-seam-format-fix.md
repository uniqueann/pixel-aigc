# 扩图格式与接缝修复

## 已修复的链路

同步消除、重绘、扩图会按实际结果 Blob 解码得到格式和尺寸，补齐 `resultImages`，资产不再把无法从 Blob URL 推断的 JPEG 标成 PNG。扩图实际结果尺寸与目标不一致时明确报错。

- 图片识别共用 JPEG、PNG、WebP 文件头检测。浏览器读取文件头，只纠正 MIME，不重编码原图。
- 工作站上传、同步工具内联与对象上传、云素材上传都按真实 MIME 传输；上传签名和 PUT 使用同一个 Content-Type。
- 工作站下载、工具箱单图及 ZIP 下载根据实际字节纠正扩展名，保留文件名主体。
- IndexedDB 历史在读取和写入时纠正已识别的格式，保留原字节、ID、时间与账号分区；无需升级旧库。不识别的历史条目不影响整个列表，实际上传或下载时会明确拒绝无效图片。
- 已上传的旧 R2 原图按真实可解码格式读取，不因错误或缺少 Content-Type 拒绝；不用重写或重新上传旧对象。权限、20 MiB 字节限制、静态图片限制继续执行。蒙版仍严格要求 PNG。
- 扩图内联与对象输入统一限制 6400 万像素；消除、重绘仍为 4000 万。元数据检查后缩为单像素触发严格解码，拒绝内容截断的图片。

文件头识别不等于完整解码验证。最终有效性仍由浏览器图片解码器、服务端 Sharp 校验。

## 接缝融合

服务端最终合成使用局部校色及多尺度融合，不增加百炼调用或模型计费。

1. 根据实际扩展方向建立边缘带：短边的 2.5%，一般 64–128 像素；再按原图边长和实际补边宽度限制。没有扩展的边不参与融合。
2. 沿边每 256 像素取一段约 32 像素深的重叠区域，低通平滑后比较颜色。排除强边缘和明显透明像素，用通道中位数估计偏移，限制在 ±24。样本不足 32 个的段不校色。
3. 局部校色在边界附近最强，向外约两倍边缘带距离渐隐；相邻段平滑插值，角落归一化组合，避免重复累加。
4. 使用 2、8、32 像素平滑尺度分离频段；颜色在整个边缘带过渡，中频在前半段恢复，高频在前四分之一恢复。内部区域在 JPEG 编码前保持原像素。
5. 每块沿边不超过 512 像素，保留 96 像素滤波上下文。原地写回背景，只保存边缘附近的背景快照，不建立整图浮点金字塔、不额外复制整个输出画布。
6. EXIF 校正后的原图按正确位置放回；透明像素与模型背景正常合成。最终 JPEG 保持 92/82/72/62 质量阶梯与 20 MiB 限制，重试编码不重复融合。

窄带会改动少量原图边缘像素；商品靠边时需要检查这一区域。融合不能修复模型造成的树干错位，也不能恢复生成背景缺失的高分辨率纹理。结构问题仍明显时，下一阶段再评估窄带重绘。

## 诊断

扩图对象读取完成后立即记录输入字节数，后续校验失败也不会把它记成未读图。读取失败保留读取耗时。

耗时表现有 `stage_ms` 新增 `imageValidate`、`colorMatch`、`seamBlend`、`encode`。结构化日志带实际/声明格式、尺寸、融合方向和带宽，不写图片内容、签名地址或密钥。融合失败明确返回合成阶段错误，不静默退回硬拼接。

本次无需数据库迁移、新环境变量或新增依赖。

## 验证与基准

自动化覆盖格式错标、字节保留、R2 原图兼容及蒙版拒绝、旧历史纠正、真实格式下载与 ZIP、连续两轮同步扩图、实际尺寸异常、40/64 百万像素边界、截断文件、EXIF 旋转、透明图、四边与角落融合、内部纹理保护、原地与独立缓冲区一致性、合成截止时间。

浏览器本地验证：实际 JPEG 以 `.png` 名称和 PNG MIME 上传，元数据正确显示为 JPEG；原字节大小保持；下载名变为 `.jpg`；页面可以正常载入该旧文件，没有运行错误。

本地合成基准使用合成颜色样例，不包含百炼生成、R2 上传下载，也不能作为线上时延保证：

| 画布 | 运行方式 | 原合成 | 修复后合成 | 说明 |
| --- | --- | --- | --- | --- |
| 5035×5035 | 5 轮中位数 | 174 ms | 1097 ms | 新增约 928 ms，测试进程峰值约 845 MiB |
| 8000×8000 | 单次融合 | 未在此进程对比 | 4409 ms | 测试进程峰值约 1569 MiB，含样例创建 |

基准可复现：

```sh
npx tsx scripts/outpaint-blend-benchmark.ts
npx tsx scripts/outpaint-blend-benchmark.ts --large
npx tsx scripts/outpaint-blend-benchmark.ts --large --blend-only --once
```

报告与合成接缝前后对照写入 `/tmp/pixel-aigc-outpaint-verification/`。大画布仍需要整图解码和 JPEG 编码，内存不是恒定开销；部署验收应检查实际运行内存与并发余量。

## 上线验收

1. 用耳机原始文件执行 3200×5035 → 5035×5035，确认大图仍走原文件 R2 上传及百炼签名 URL。
2. 下载为 JPEG，再上传扩至约 6699×5097；另外验证页面直接继续扩图、旧历史恢复继续扩图、已有旧 R2 对象直接复用。
3. 在 100% 与 200% 检查树干接缝、商品文字、角落和贴边主体，确认色差减弱且没有新增明显重影、光晕。单独记录模型纹理错位。
4. 回归平台模式 1600×1600，工具箱单图和 ZIP 下载；验证大于 3.5 MiB 结果的签名下载、资产保存与后续编辑。
5. 查看新增阶段耗时及大画布内存。确认失败处理沿用现有积分规则。

当前附件只有截图，尚未用用户真实耳机原图和实际生成结果验证融合效果；真实百炼/R2 验收须在部署后完成。
