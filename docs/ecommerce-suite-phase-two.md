# 电商套图阶段二：单槽位实现与验收边界

基线：`main / 8a5971b`，PR #194 已合并。实现分支：`feat/ecommerce-suite-phase-two`。

本阶段已实现单槽位的项目保存、资产上传、报价、原任务提交、账本展示、结果登记、候选选用与重新打开。当前证据分为真实独立 PostgreSQL、模拟供应商和浏览器合成 HTTP 数据，不能替代真实商品、目标环境 R2 或实际供应商验收。

## 1. 页面与保存

- `/ecommerce` 提供列表、新建、复制配置及回收站；`/ecommerce/:id` 打开工作台。复用全局导航、主题、现有资产选择器及图片下载设施，页面按路由加载。
- 创建向导先预留主体资产身份，幂等保存云端草稿，再直传临时对象并完成校验。主体图没有登记为 ready 时不能报价或提交；中断的创建资料和图片保留在本机，可继续完成。
- 三个子类均创建七个稳定槽位，推荐项仅作为风格。商品事实显式确认后才进入生成要求和版本快照。尺寸图、文字图层、工作站回填及平台导出在后续阶段接入。
- 配置、单槽位要求、当前指针分别使用 `revision / draftRevision / headRevision`。配置与要求各有 800ms 防抖保存；本地编辑立即备份，修订冲突保留副本并提供读取云端或另存入口。
- 浏览器按账号、运行环境和项目隔离 IndexedDB。完整备份逐页读取全部槽位历史、逐张校验并保存原图和结果 Blob，全部落盘才显示完整。存储失败可下载含图片恢复包；包内不含可执行队列、报价、提交许可或签名地址，导入仍在第四阶段接入。
- 图片访问通过资产 ID 重新授权，内存地址在过期前更新；对象读取或下载失败不触发生成。下载冻结已选底图的版本、真实像素和扩展名，当前不宣称完成平台预检或图层合成导出。
- 宽屏预览可完整容纳时吸顶；900px 及以下预览在上、配置在下，正常滚动；窄屏和短屏吸底栏回退文档流。

## 2. 原任务与费用

服务端对照类目模板决定路径，一次只接受一个槽位。主图复用已保存原图，细节槽位必须有真实细节输入；场景类槽位走已有 `image_edit` 服务，不直接调用供应商。

报价读取实时模型目录，通过原供应商的纯参数映射得到实际分辨率、预期尺寸和警告；候选上限及可用分辨率来自目录。报价内容由服务端持久保存，确认前展示合成后的完整要求、候选张数、单价和合计。所有成功候选仍按原账本计费，选用一张不改变已发生费用。

单槽位同样需要持久报价和操作凭据，因此提前实现 `suite_quotes / suite_batches / suite_operations` 的最小子集。接受报价、原 `BillingPort.reserve`、job/items 创建与操作绑定在同一事务中提交；供应商和对象 I/O 在事务之外。没有父批次收费状态机，也没有套图后台领取处理器。

- 通用 `/tasks` 创建入口拒绝客户端声明的套图来源；套图服务在已验证项目、槽位、报价和操作上下文后创建真实 `ecommerce` 来源。任务中心沿用原 `image_job` 身份及账本，返回可定位到原项目和槽位；`suite_batch` 聚合仍待第三阶段。
- 提交前先落本机原请求。连点复用同一次提交；存在待确认请求时只能 GET 查找原批次。网络结果不明、刷新、重登及查询均不会自动再发收费 POST。
- 原服务推进已提交任务，结果登记只读取原 job/items、验证图片并复制为项目长期资产。生成结果按原 job+ordinal 幂等创建不可变版本；转存失败只重做转存，不重新生成或结算。
- 单候选首次结果仅在无旧成品、当前指针未变化且无编辑草稿时自动选用；其他情况保存候选，等待显式选择。多候选不自动覆盖。
- 原任务已清理时仍保留原请求、job ID、版本及长期图片，不把任务不存在解释为尚未执行。账本无法读取时明确显示费用未知。

## 3. 数据与启用

迁移文件：[20261016224010_ecommerce_suite_phase_two.sql](../supabase/migrations/20261016224010_ecommerce_suite_phase_two.sql)，由 Supabase CLI 生成。七张表采用 `aigc_api`、当前账号与运行环境 RLS，并以复合外键约束项目、槽位、资产和版本。普通角色不能覆盖版本或报价内容；Data API 的 `anon / authenticated` 没有直接表权限。

持久对象采用 `suite-assets/<scope>/<userId>/<projectId>/<assetId>-<sha256>.<扩展名>`。相较阶段一的占位命名增加内容哈希，防止并发完成上传时相互覆盖。上传完成会验证实际字节、格式、像素、单帧和完整解码；原图片任务读取套图输入时同时验证路径与 ready 资产登记。

目标环境开放顺序：

1. 保持 `ECOMMERCE_SUITE_ENABLED` 关闭，使用正常迁移流程应用新增迁移并核对实际 `aigc_api` 权限。
2. 核对 R2 临时对象生命周期、直传 CORS、对象续签与代理读取；核对当前模型和原图片维护服务。
3. 在目标环境验证真实商品的一次报价、原任务、实际账本、版本、刷新与下载，并补齐对应真实样本证据。
4. 验收后设置 `ECOMMERCE_SUITE_ENABLED=true`，账号响应才返回功能能力，导航和服务端入口一起开放。
5. 回退时先关闭开关，保留数据、版本和原任务账本；不删除表或自动重提任务。

本次开发没有修改远端数据库、对象桶或部署环境。独立 PostgreSQL 测试使用本机空白临时数据库，明确拒绝业务连接；Mock 供应商不会产生真实费用。
