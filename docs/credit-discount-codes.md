# 积分充值折扣码接入与验收

更新日期：2026-10-09。参考 EDM 的可选折扣输入、代码规范化和平台验证，复用 AIGC 独立的一次性订单与积分账本。

## 一、首期规则

- Dodo Payments 与 Creem 均支持，用户选择哪个通道就验证该通道；同名代码在两个商户环境的规则可以不同，切换通道后必须重新应用。
- 商户后台管理代码，应用只读验证，不建券库、发券后台或自动写入活动。
- 代码去首尾空格并转大写，只支持 1–14 位字母或数字，空值不传。代码不硬编码，不保存到浏览器持久存储。
- 仅支持单个普通百分比折扣，折扣大于 0% 且小于 100%；不支持固定金额、零元、叠加、多币种封顶、首购资格或每客户限次。可以限制总次数、有效期和指定套餐。
- 券的商品范围必须非空，且全部是该通道、该环境已配置的 AIGC 商品。允许只覆盖部分套餐；无商品限制和含 EDM 商品的券均拒绝。
- 100 / 320 / 1150 积分数量不因折扣改变。套餐原价分别为含税 $2.99 / $6.99 / $19.99，金额按整数美分保存。

## 二、接口与交互

`POST /api/credits/discount-preview` 需要已登录且有效的 AIGC 成员：

```json
{"provider":"creem","code":"AIGC10","expectedCurrency":"USD"}
```

返回当前通道各套餐的适用状态、原因、原价和预计优惠。示例代码仅用于说明，代码发布不会创建该商户活动。未知码、过期、未生效、已用完、商品不适用分别提示；缺少只读权限或平台不可用返回 503，不显示为无效码。

充值面板点“有折扣码？”展开输入，可应用、修改或移除。有效套餐显示原价、优惠百分比和预计应付；不适用套餐注明原因和“按原价购买”。填写但尚未验证的代码不能默默按原价下单。修改代码立即取消旧验证并废弃报价；关闭面板、切换账号、通道、币种或套餐价时清空折扣会话，迟到响应不能恢复旧报价。

下单接口兼容原无优惠请求，新增可选 `discountCode` 与 `expectedPayableAmount`。有优惠时必须带预计应付，服务端重新查询规则并核价；发生变化返回 409 `DISCOUNT_CHANGED`，前端清除报价并要求重新应用。同一订单号重试使用已冻结的报价和付款链接，不以之后的目录价或券失效覆盖已有订单。

预览与新折扣订单的规则重查共用独立 `payment_discount` 限流：每账号、每环境 60 次/小时、并发 2，租约与图片处理额度隔离。新订单仍遵守既有 20 次/小时创建限制。

## 三、到账与退款

订单 `amount` 永远保留原价，`quoted_discount` 保存下单预计规则和应付，`paid_amount` 与 `paid_discount` 保存核验后的最终实付和优惠。没有优惠的旧订单仍按原价契约处理，不需要回填。

- Dodo 下单传单元素 `discount_codes`；关闭结账页额外输入优惠和币种切换。收据只能出现被冻结的单码，并核对实际总额。
- Creem 下单传可选 `discount_code`；付款页仍可新增、更换或移除代码。重新查询 Checkout、商品及交易，按最终合法单码及 `amount_paid` 到账，原报价只作预计。
- 最终代码与预计代码相同时可使用冻结规则；不同代码需从该环境商户只读查询静态规则并核对商品、类型、代码与折扣比例。历史收据不因当前到期或总次数用完被否定；已保存的最终收据不可被后来回调改写。
- 百分比取整只接受精确结果相邻的向下或向上整数美分，不使用任意金额容差。Creem 含税商品同时核对订单、交易中的税前优惠字段、含税应付及实付，不把税前优惠直接视为现金优惠。缺少实付或查询尚未反映最新状态时返回可重试错误。
- 验签、metadata、单件、一次性、USD、账号、运行环境及 EDM 隔离保持原规则。无法证明合法实付时订单进入 `review`，停止发分并冻结该环境账户的收费操作。
- 到账仍由 worker 事务调用 `complete_credit_order_with_discount`，锁定订单、写余额和 `order:<订单UUID>` 流水，重复回调与补偿只发整包积分一次。
- 退款先到时 `record_credit_order_payment` 只保存核验实付，不发积分；后续撤销用实付作分母。退款与付款乱序不会误发整包积分。
- 现金退款仍需人工审核，按累计退款金额 / 最终实付金额计算应收回积分并向上取整。例如实付 $2.69 的 100 积分订单累计退 $1.07，累计收回 40 积分；全额只能退 $2.69。代码过期或活动结束不改变该订单的已保存实付与可退额度。

## 四、商户配置与发布

1. 在两个平台的 TEST 环境分别配置测试券，限定为该平台 TEST 的 AIGC 三档商品或指定子集。建议使用独立测试代码、10% 优惠、明确有效期与总使用上限，不复用 EDM 的券。
2. Creem AIGC 专用 TEST 与 LIVE API 密钥增加只读 `discounts:read`，保留现有四项运行权限；不授予 `discounts:write`。平台若不支持修改现有密钥权限，应创建替代专用密钥并更新对应服务端变量。新部署核验完成、旧部署退场后再停用旧密钥，避免环境变量更新后既有部署仍引用旧密钥。权限变更与真实现金操作单独核对。
3. Dodo 运行密钥应能读取折扣记录；通过官方 API 核对 `type=percentage`、基点数、`restricted_to` 和次数。禁止商品默认折扣、购买力折扣、任意金额及高级客户资格规则。
4. 先应用 `supabase/migrations/20261008161051_credit_discount_codes.sql`，再部署代码。迁移仅改 `aigc`，保留旧九参数原价到账函数，不创建重载，也不改 EDM 或共享 Auth。
5. 密钥继续使用 `AIGC_<通道>_<TEST或LIVE>_API_KEY`，本机私有环境配置和 Vercel Secret 保管；无新增前端密钥或活动代码变量。TEST/LIVE 不回退。
6. 新规则继续使用既有独立 webhook；无需创建或替换回调。Creem 新订单仍由 `AIGC_CREEM_ENABLED` 控制。折扣先在 TEST 联调部署验收；密钥轮换保留各环境既有开关值，不把权限配置视为正式折扣付款验收。
7. 发布或回滚不删除商户券、收据快照和旧订单需要的密钥。回滚到不支持优惠的代码不能处理已付折扣订单，应优先保留新版到账服务，只暂停新下单。

## 五、验收清单

| 场景 | 验收要求 |
| --- | --- |
| 普通购买 | 无代码三档保持原价，原套餐积分到账一次 |
| 有效优惠 | 两通道分别查规则、折后支付、核对实付与整包积分 |
| 部分适用 | 支持限定套餐，其他套餐明确按原价购买且不传码 |
| 失效与异常 | 格式、未知、未生效、到期、用完、EDM/全商品券、固定额/零元/高级资格均拒绝，权限/网络错误可区分 |
| 付款页变化 | Creem 新增、更换、移除代码，预计和最终快照分别正确 |
| 历史与改价 | 同订单重试、活动结束、已保存收据后商品改价不改写订单 |
| 幂等与乱序 | 实际签名回调、重放、查询补偿、退款先到，只记一次整包充值 |
| 退款 | 实付比例、连续部分和全额、重复旧事件、人工冻结与取消、争议冻结 |
| 隔离与限流 | 两独立登录账号、local/preview/production、EDM、通道切换、迟到响应、60次/小时与并发2 |

本地自动化使用受控支付响应；PGlite 执行真实迁移、SQL、事务、RLS 和数据库限流，但不等同于远程多连接压力测试或商户 TEST/LIVE 实际付款。交付记录应分别填写本地检查、远程迁移、权限配置、商户测试与真实付款状态。
