# 自由画布：生成血缘（成组与连线）方案

给接手实现的 agent：这是 `#282` 的 shape 方案，覆盖"同批结果成组"与"派生关系可见"。看完能直接动手，不需要再回来问设计意图。

## 状态（2026-11）

- **阶段 1 已发布**（#296）：选中一张生成结果时，同批其它结果加虚线框、派生结果画虚线到源节点。零数据改动、不动 schema。
- **阶段 2（`scene.groups` 持久组）与阶段 3（常驻连线 + 图层折叠）暂缓**，#282 已按此结论关闭。

暂缓的原因：阶段 1 已经回答了"这几张是同批的"和"它从哪来"这两个真实问题；阶段 2 的增量收益（组框、标题、一键全选）目前可以用"框选 + 图层面板"凑合，而代价是 schema 迁移、`ResolveGenerationCommand` 的成员替换、以及"组与复制/粘贴/重试/删除"的长期语义维护。

**重新开启的条件**（满足任意一条再回来做阶段 2）：
1. 实际使用中出现"结果多到光靠虚线框已经分不清批次"的反馈；
2. 需要按组批量操作（整组再生成、整组导出）；
3. 需要给批次命名/加备注。

触发时按本文第 4–6 节的模型与阶段拆解执行，无需重新设计。

## 1. 目标与判据

**要回答的用户问题**：这张图是从哪来的？这 4 张是不是同一次生成的？我按哪张再裂变过？

**成功判据**
- 一次生成 4 张后，用户能在画布上看出来它们是一批，并能整组移动/删除（不用逐张点）。
- 从某张图裂变/图生视频得到的结果，与源图之间的来源关系可见（可关闭）。
- 旧项目打开不报错，退化为当前表现（无组、无连线）。
- 分组信息随项目持久化，导出/导入 JSON 往返一致。

**产品意义**：这是这个产品区别于通用图片画布的地方——血缘数据一直都在（`GenerationJob.parentGenerationId` / `retryOfGenerationId` / `inputAssetIds`、`Asset.generationId`），但从未被画出来。

## 2. 现状（数据层已有什么、缺什么）

已有的：

| 位置 | 字段 | 说明 |
|---|---|---|
| `Asset` | `generationId?` | 这个素材由哪次生成产出（`canvasRecovery` 里已写入） |
| `GenerationJob` | `outputAssetIds[]`、`parentGenerationId?`、`retryOfGenerationId?` | 一次任务的产出与父子链 |
| 节点 id | `generated-node:<taskId>:<ordinal>`、`generation-node:<taskId>:<index>` | 结果与占位节点都带任务前缀 |
| 派生草稿 | `drafts.derived.sourceNode` / `sourceAssetId` | 当前这次派生从哪张图来 |

缺的：**"哪几个节点属于同一组"没有显式记录**，只能靠 `asset.generationId` 或节点 id 前缀反推。反推的问题是：`⌘D`/`⌘V` 出来的副本共享同一个 `assetId`，会被自动算进原组；用户也没法把某张图移出组。

## 3. 核心设计决定：组是"派生容器"，不是嵌套容器

组**不拥有自己的变换**：它的位置和尺寸由成员包围盒算出来。

为什么不做成 Figma 那种嵌套 group：
- 嵌套要处理父子坐标、组缩放/旋转回写、z-order 嵌套，和现在的 `ActiveSelection` 批量变换会互相打架；
- 我们的批量操作（多选移动/缩放/删除、层级、对齐参考线、`⌘D`、`⌘C/⌘V`）已经按"选择集"建好了，组只要能**一键全选**就够用。

于是"组"承担三件事：**视觉外框 + 一键全选 + 标题**。派生连线是第四件事，按节点对计算。

## 4. 数据模型（阶段 2）

```ts
// src/editor/types/document.ts
export interface SceneGroup {
  id: string
  kind: 'generation' | 'derived'
  /** kind === 'generation'：产出这批结果的生成任务 */
  generationId?: GenerationId
  /** kind === 'derived'：派生结果的源节点（连线起点） */
  sourceNodeId?: NodeId
  title: string
  nodeIds: NodeId[]
}

export interface Scene {
  // …现有字段
  groups?: SceneGroup[]   // 可选字段：旧快照没有它，等同于"无组"
}
```

约束（写进校验与命令层）：
- 组必须至少 1 个成员；成员必须存在且属于同一场景；一个节点最多属于一个组。
- 删除节点时从组里移除，组空则删组（否则快照里出现悬空 id）。
- `ResolveGenerationCommand`（占位 → 结果）需要把占位 id 换成结果 id，而不仅是加节点（**这是持久化侧最主要的坑**）。
- 旧数据迁移：无 `groups` 字段 = 无组；不做"按 generationId 自动补算"（避免用户打开旧项目时版面突然多出一堆框）。

## 5. 交互规范

| 场景 | 行为 |
|---|---|
| 组框 | 浅色虚线包围盒 + 左上角标题条（`本次生成 4 张 · 14:32`），层级恒在成员之下 |
| 点组框/标题 | 选中组内全部节点（复用 `selectNodes(ids)`，进入现有多选态） |
| 点单个节点 | 只选该节点（不变） |
| 组内拖动 | 点组框全选后拖动 = 整组移动（复用 `ActiveSelection`，已有能力） |
| 层级 `⌘]/⌘[` | 只作用于选中节点；组内相对顺序保持 |
| 框选 | 组不参与命中（框到的节点各自入选择集） |
| `⌘D` / `⌘C/⌘V` | 副本**不进组**（保持"复制 ≠ 血缘"，与 `⌘D` 不扣积分的语义一致） |
| 删除 | 删成员即出组；删光即删组 |
| 图层列表 | 组显示为可折叠标题行，成员缩进（阶段 3） |
| 派生连线 | 从源节点右边中点到结果节点左边中点画细线（Fabric `Line`，`evented:false`、`excludeFromExport`），可全局开关，默认开 |
| 重试任务 | 独立批次；连线指向原任务的第一张结果（多条可合并成一条虚线） |

## 6. 分阶段（建议先做阶段 1）

### 阶段 1：临时高亮（0.5–1 天，零数据改动，不动 schema）

选中一个节点时，同批的其它节点临时高亮（浅色虚线描边 + 右上角小圆点），选中派生结果时同时画出到源节点的虚线；松开选择即消失。

- 批次判定：优先 `assets[node.assetId].generationId`，退化到节点 id 前缀 `generated-node:<taskId>:` / `generation-node:<taskId>:`。
- 派生判定：`GenerationJob.parentGenerationId` 指向的产出素材 → 找到画布上对应节点。
- 全部走 `paletteRef.current.accent`，颜色随主题；不写任何数据、不进撤销栈。

**为什么先做这个**：这段成本最低，能验证"用户是否真的需要组"。如果验证下来大家只是想要"这几张是同批"的提示，阶段 2 的 schema 迁移就可以不做。

### 阶段 2：持久组（1.5–2 天）

`scene.groups` + 组框 + 标题 + 全选入口 + 快照校验/迁移 + `ResolveGenerationCommand` 更新成员 + 创建生成任务时登记组。

### 阶段 3：常驻连线与图层折叠（1 天）

连线常驻 + 开关；图层面板按组折叠；可选：组标题右键"再生成一版"。

## 7. 需要拍板的三点（附推荐）

1. **副本是否进组**：推荐**不进**。理由：`⌘D`/`⌘V` 是"复制节点"，不产生新的生成记录；进组会让"组 = 血缘"这个定义被稀释，也会让用户在 `⌘D` 后看到组变大 4 个成员。
2. **重试任务算不算同一批**：推荐**独立批次**（`retryOfGenerationId` 只用于连线，不合并组）。理由：重试可能是不同模型/参数，成组会让人误以为同参数产出。
3. **组框是否参与命中**：推荐**不参与**（点组框=全选，不做拖动定义域）。理由：现有命中逻辑基于节点矩形（`stackAtPoint`），组框参与会让 `⌥` 穿透和框选都变复杂。

## 8. 测试清单（阶段 2 为准）

- 组命令：建组/拆组/成员增删各一条撤销记录（复用 `CompositeCommand`）。
- 快照：含 `groups` 往返一致；缺 `groups` 的旧快照可读；悬空成员/重复成员被拒绝。
- 回归：`⌘D` 后副本不在组内；删成员→组收缩；删光→组消失。
- 渲染：组框层级在成员之下；组框不参与 `stackAtPoint`；连线 `evented:false`。
- 阶段 1 额外：批次推导对旧数据（只有节点 id 前缀）也能工作。

## 8.5 阶段 1 实现记录（已落地）

- 纯逻辑 `src/features/free-canvas/lineage.ts`：`taskIdFromNodeId` + `resolveLineage`。
  - **同批判定用节点 id 前缀**（`generated-node:<taskId>:` / `generation-node:<taskId>:`），不用 `asset.generationId` —— 因为 `⌘D`/`⌘V` 的副本共享素材、但没有任务前缀，用 id 前缀才符合"副本不进组"的决定。
  - **派生判定用 `asset.generationId` + `parentGenerationId`**：父任务的 `outputAssetIds` 里、且画布上还有节点的才算源。
- 舞台渲染：同批节点画 1px 虚线框（`opacity .55`），派生关系画 1px 虚线（越过左右位置自动接最近的边），全部 `selectable:false` / `evented:false` / `excludeFromExport`，只读提示、不进撤销栈，取消选择即清除。
- 已验证：无选中 → 0 覆盖物；选中派生结果 → 2 个同批虚线框 + 1 条源连线；选中副本 → 0 个同批框（但仍有 1 条派生线：副本的素材确实来自那次生成，这是素材级关系，不是组）；取消选择 → 全部清除；无异常。
- **阶段 2 还要补的**：显式 `scene.groups`（成员表、标题）、组框层级在成员之下、`ResolveGenerationCommand` 替换成员、快照校验与旧项目兼容、图层面板折叠。

## 9. 风险清单

- **`ResolveGenerationCommand` 的成员替换**最容易漏：占位 id 消失、结果 id 新增，组里要同步，否则快照校验会抛"成员不存在"。
- 组框与参考线/焦点环/图层叠加时的视觉噪音：三套虚线框同时出现会很乱，阶段 2 需要定优先级（建议：选中 > 组框 > 参考线，参考线只在拖动时出现）。
- 大画布性能：组框每次拖动都要按成员包围盒重算，成员多时注意只重算受影响的组。
- 连线在缩放很小时会糊在一起，建议 <30% 缩放时只画组框不画连线。
