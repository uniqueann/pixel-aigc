# 智能抠图上传性能优化：第一批

## 范围与依据

2026-10-15 正式站单次样本：2160×2880、4,780,641 字节、带已有透明度的 PNG；完整结果约 22.852 秒，其中客户端上传 11.035 秒、处理 API 9.137 秒、浏览器结果读取 2.025 秒。该素材不能代表自然背景商品首次抠图的平均值。

本批解决同图重复上传、上传竞争和阶段不可观测的问题。原图字节、尺寸、腾讯识别方式、透明度恢复、费用确认、失败退款及仅手动重试维持原行为。部署区域、输入压缩、识别缩略图和蒙版回传不在本批运行时改动内。

## 原图上传复用

- 仅对走对象传输的大图启用；小图仍按原有阈值内联提交。
- 对真实 MIME 校正后的原始字节计算 SHA-256；新选择的文件即使实例或名称不同，内容相同仍可复用。大小、名称相同但内容不同不会命中。
- 缺少 Web Crypto 时只按同一个 Blob 实例复用，不使用名称、大小或修改时间猜测内容。
- 复用范围为当前浏览器内存会话中的 `userId + runtimeScope`。切换账号、退出或切换运行环境会清空记录并中止旧上传；旧会话的迟到结果不能重新写入。
- 仅保留摘要、对象键和完成时间；不把原图、摘要或签名地址写入持久化存储、业务请求或日志。摘要计算期间仅短暂读取原始字节，计算结果由弱引用关联文件实例。
- 成功上传复用 30 分钟，最多保存 20 条完成记录，按最近使用顺序淘汰；不缓存失败上传。签名上传地址有效期与已上传对象的复用期是不同概念，本批只复用对象键。
- 同内容并发上传合并为一个请求。单个使用者取消不影响其他使用者；全部取消或会话失效时才中止共享请求。
- 上传最多同时两个，排队不占腾讯处理名额；原有抠图批处理并发仍为三个。取消排队项不会发起上传。
- 处理 API 返回 `OBJECT_NOT_FOUND` 后失效对应的上传缓存并结束本次调用；下一次用户主动处理才重新上传，不在当前调用内自动再次生成。
- 复用对象只省略上传，不缓存或合并用户主动提交的抠图任务。原有下载失败仅重试下载、换背景复用透明 Blob 的行为不变。

## 上传耗时

共享 `uploadTaskInput` 保留 `validateMs`、`signMs`、`uploadMs`、输入和成功上传字节数，增加：

| 字段 | 含义 |
|---|---|
| `directUploadMs` | 发起 PUT 到响应头或失败；含连接、请求传输与服务端等待 |
| `directStatus`、`directOutcome` | 可见的 HTTP 状态，或网络失败、取消等有限状态 |
| `fallbackEncodeMs` | 直传网络失败后转换 Base64 的耗时 |
| `fallbackUploadMs` | 原有后端回退上传耗时 |
| `transport` | 最终直传或回退路径 |
| `elapsedMs` | 校验、签名、直传及可能的回退流程总耗时 |
| `networkTiming` | 浏览器完整暴露时才记录 DNS、建连、TLS、请求到响应与响应读取阶段 |

修复回退路径覆盖直传耗时的问题：`uploadMs` 现在累加直传和回退两个请求阶段；Base64 编码另列。原有只有网络异常才走回退、HTTP 错误直接失败的行为不变。

跨域没有 `Timing-Allow-Origin`、Resource Timing 缓冲未记录或时序不完整时，`networkTiming` 缺省，不能解释为 DNS 或 TLS 实测为零。建连时间包含 TLS，不能重复相加；请求到响应也不能称为纯上传速度。观测接口异常不会影响成功上传。

抠图控制台事件 `bg-remove-upload` 记录 `source=upload/cache/inflight`、摘要方式、计算耗时、排队与等待、上传阶段和结果状态；不记录实际摘要、文件名、对象键、URL、凭证或原始网络错误。`bg-remove-client` 增加本次输入复用来源，用于关联完整处理耗时。

2026-10-16 Chrome 本地流程验收使用 5,538,591 字节 PNG，两次重新选择并主动处理，结果为：申请地址 1 次、原图 PUT 1 次、处理 POST 2 次，服务端校验上传内容 SHA-256 与输入文件相同。真实前端传输代码连接的是本地模拟存储和模拟处理响应，未调用腾讯、未扣积分。

该验收中第一次处理 908 ms、第二次 280 ms；模拟上传主动加入 600 ms 等待，因此该差值只验证缓存流程，不能当成正式站加速比例。浏览器日志分别显示 `source=upload` 与 `source=cache`，第二次未发生网络上传。

本地证据位于 `/tmp/pixel-bg-remove-upload-20261016/`，包括 `browser-evidence.json`、`browser-verified.jpg` 和完整测试日志。发布后仍需以同一组自然背景、透明商品、细线边缘与 EXIF 素材复测，比较首次和重复选择、上传字节数、完整结果时间、成功率、尺寸和边缘质量。
