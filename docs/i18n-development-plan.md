## 1. 交付目标和范围

最终交付应满足以下要求：

1. 首次访问且没有语言选择记录时，在登录页首次渲染前根据浏览器语言初始化；用户手动选择始终优先。中文保留为无法获得有效语言信息时的回退，登录页和设置的“通用”页均可手动切换。
2. 语言切换即时更新当前页面，刷新后可以恢复选择。
3. 登录前页面、主导航、设置、首页、8 个图片工作站工具、4 个工具箱工具、自由画布、邮件助手、资产、任务中心、积分与充值均支持英文。
4. 9 篇帮助文章以及关于、隐私页面提供对应英文内容。
5. 已迁移页面没有缺失资源键、裸露翻译键或意外的中文系统提示。用户内容、品牌名称、模型名称和原始结果按原内容显示。
6. 切换语言不清空表单、上传文件、蒙版、画布草稿、选中项、批量队列或已获得的结果。
7. 切换语言不会额外提交生成、充值、重试、退款或其他业务写请求，不改变原任务编号和幂等标识。
8. 同一组业务输入在两种界面语言下产生相同的生成参数、模型选择和计费请求。
9. 注册验证、重发验证和密码恢复邮件必须包含可直接完成操作的英文主题、说明及按钮，并完成真实收信与回调验收；这是 P6 开始前和正式英文入口开放前的必需条件。
10. 新价格目录、折扣报价、充值订单及支付请求统一使用 USD；中文和英文界面显示同一美元报价，不提供人民币新充值入口或按语言切换币种。

本轮保持既有生成扣减积分、免费额度、计费周期、模型策略、账号及运行环境隔离。充值货币统一为 USD，沿用现有美元套餐报价。邮件的“输出语言”仍由原邮件参数和用户偏好决定，不跟随界面语言自动变化。存量订单保留原始金额与币种，不能将历史人民币交易改写为美元。

首版不新增云端语言偏好字段，不修改数据库表或账本函数。跨设备同步语言、其他语种、全站语言路由前缀、区域定价及模型 Prompt 的语言优化可独立立项。首次浏览器语言探测和认证邮件双语支持纳入本轮范围。

第三方支付托管页、Google 授权页仍记录其实际语言及影响范围。Supabase 认证邮件虽然由平台发送，但模板可配置，本轮纳入 P5A 必做项。模板需要完成托管项目配置及真实收信验收，不能用仓库中存在 HTML 文件替代配置生效和邮件闭环验证。本次计划修订不执行任何线上 Auth 配置变更或真实邮件发送。

## 3. 先冻结的技术规则

### 3.1 国际化实例与资源

- 使用 `i18next + react-i18next`，安装时验证与现有 React 18、TypeScript 5 和构建链的兼容性，提交锁文件；不顺带升级 React、AntD 或 Vite。
- 由 i18next 实例提供当前语言，避免再建立一个独立、可能失去同步的语言状态源。
- 翻译资源按业务模块拆分，首版随应用打包，不依赖额外的翻译接口或远程资源服务。
- 固定 `supportedLngs`，校验本地缓存；仅在语言分区尚未初始化且没有用户选择记录时执行一次浏览器语言探测，具体优先级按第 3.2 节执行。
- 开发阶段允许缺失英文资源暂时回退中文；最终发布前以资源检查和页面验收消除计划范围内的缺失。
- 语义键、类型声明及调用方式在 P0 锁定。默认采用类型化语义键方案；确认所选 i18next 版本的字符串键与 selector 配置，避免依赖大版本默认值。
- 增加布尔构建开关 `VITE_I18N_ENABLED` 控制英文入口，缺省关闭；开发和预览验收时显式启用。关闭时即使缓存为英文也使用中文，中文页面仍经由相同资源层渲染。
- 在全局中文默认回归通过后再逐模块迁移；不使用运行时扫描 DOM 替换文本的方式。

### 3.2 语言选择与本地记忆

首版界面语言只保存在当前浏览器，不加入现有 `usePreferencesStore` 的云端字段补丁。

此选择减少偏好接口、初始化合并和旧版本兼容改动。换设备后不会自动恢复此前手动选择的语言，会先按新设备浏览器初始化，需要时再手动调整。后续云同步可以复用已有 JSON 偏好体系，未必需要新增数据库列，但仍需扩展 schema、接口、缓存和账号切换规则，单独验收。

建议缓存键为 `pixel:ui-locale:v1:<origin>:<runtimeKey>:<owner>`：

- `runtimeKey` 根据现有构建模式和云模式生成，与应用已有本地缓存分区规则保持一致。
- 登录前使用匿名分区；登录后使用当前用户分区，不改变历史、任务或偏好本身的身份规则。
- 缓存记录保存 `locale` 和来源 `manual/browser/fallback`，有效记录同时表示当前分区已经初始化；浏览器探测结果不能伪装成手动选择。
- 当前分区的有效手动选择优先于自动初始化结果。已有有效初始化记录时复用，不因系统语言变化、刷新、重新聚焦或重新进入登录页再次探测。
- 账号有手动保存值时使用该值；账号仅有自动初始化记录时，本次匿名会话明确的手动选择可取代该自动值。首次进入且无记录的账号继承当前匿名选择及其来源，无可继承记录时再按首次初始化规则处理。
- “本次匿名会话明确的手动选择”由当前会话交互标记判定，不能把历史匿名缓存误判为刚发生的操作。
- 用户在已登录状态下的修改只写当前账号分区，不覆盖匿名值；退出后恢复匿名选择。
- A 账号切换至 B 账号时读取 B 的选择，不能把 A 的选择自动写入 B。
- 存储不可用时仍允许当前页面切换；本次页面会话内不重复探测。刷新后若无法恢复记录，按首次访问规则初始化，不阻塞应用。
- 如处理跨标签页存储事件，只接受当前身份分区的变化。
- 现有“恢复个性化默认”保持原范围；语言选择不隐式加入其云端重置请求。

首次初始化规则：

1. 英文功能开关关闭时使用中文，不执行探测或新建自动初始化记录；保留已有选择，不将强制回退写成手动选择。以后开启英文时，没有初始化记录的用户仍可执行首次探测。
2. 没有有效缓存时，优先按 `navigator.languages` 的偏好顺序匹配 `zh` 或 `en`，并兼容只有 `navigator.language` 的浏览器；`zh-*` 归一为 `zh-CN`，`en-*` 归一为 `en`。
3. 浏览器提供有效语言但均不在支持范围内时，使用英文；读取不到、为空或无法识别有效语言信息时使用中文。
4. 探测在首次 React 渲染前同步完成，使用本地资源，避免先显示中文登录页再切换英文。只读取浏览器本地语言信息，不增加 IP 定位或外部识别请求。
5. 写入初始化结果及来源；用户后续手动切换立即成为当前分区的优先选择。损坏缓存按无有效记录处理，不阻止后续手动选择。

“从未选择”以当前浏览器、运行环境和身份分区的本地记录为边界；首版没有云端语言同步，不能推断用户是否在另一设备选择过语言。

初始化先读取匿名配置并按以上规则补齐；账号身份就绪后再应用当前账号的配置。账号识别不能成为登录页显示翻译资源的前置条件。

### 3.3 与业务状态的边界

- 国际化初始化放在应用入口，与 AntD 的 `ConfigProvider` 联动。
- 不以语言作为根组件、路由、画布或业务页面的 `key`，避免语言切换导致整页卸载重建。
- 语言不进入生成参数、价格版本、请求指纹、任务身份或服务端数据查询缓存键。
- 翻译函数可以成为展示计算的依赖；不能因此重新触发提交、恢复、轮询初始化或项目载入。
- 异步失败优先保存错误码和参数，由当前渲染语言展示，避免结束时显示提交时缓存的旧语言文案。
- 已结束的临时 Toast 不追溯修改；仍在页面展示的错误、任务状态和说明应随语言更新。
- `shared/` 和 `server/` 不导入 `src/i18n`、React Hook 或浏览器存储。

### 3.4 认证邮件的首版交付方式

- 首版采用英文在前、中文在后的双语认证邮件，主题和操作按钮包含英文；覆盖注册验证、重发验证及密码重置。当前已启用且会到达用户的安全通知也纳入核对，不借本轮新增通知类型。
- 选择双语模板是为了在不增加云端语言字段的前提下覆盖首次注册、旧账号、未登录重发和找回密码。浏览器语言与 `localStorage` 不会自动传入 Supabase 邮件模板；模板中的 `.Data` 对应用户元数据，不能假定它代表本次未登录页面的语言。
- 后续如要求严格按当前界面语言发送单语言邮件，需要单独验证各发送路径的语言上下文与旧账号回退，不能只在注册时写入一个字段就宣称完成全链路本地化。
- 仓库保存模板源码、主题及变更说明；托管项目还需实际更新 Auth 邮件配置并记录生效版本。当前仓库没有可直接用于本地邮件配置的 `supabase/config.toml`，本地预览方案需在 P0 明确。
- 既有 [Auth 配置文档](auth-domain-branding.md) 记录 ContentUp、AIGC、EDM 共享 Auth。P0 必须核对当前共享关系，模板保持已确认的品牌及原链接变量，不把其他产品的回调硬编码到 AIGC；P5A 覆盖仍在共享范围内的产品回归。
- 真实收信和回调验证是必需交付，不以模板预览、配置保存、HTTP 成功或邮件发送请求成功替代；P5A 未完成时不能进入 P6 发布验收或开放正式英文入口。

### 3.5 USD 单一新充值币种

- 所有新充值价格目录、折扣报价、订单和支付请求固定 USD，不按语言、浏览器、地区或账号偏好选择币种。美元收款策略独立于 `VITE_I18N_ENABLED`，不能因关闭英文入口恢复人民币新充值。
- 以现有 `CREDIT_PACKS` 的 USD 价格作为本轮基线，金额使用美分整数；不把人民币数值直接改标为美元，也不做前端汇率换算。
- 调整 `server/payments/providers.ts` 的币种选择，取消默认回退 CNY。实现时可固定 USD 或仅接受 USD 配置；若保留 `AIGC_CREDIT_CURRENCY`，非 USD 值应阻止开放新充值，并给出配置错误，不能继续创建其他币种订单。
- 新目录及创建入口的类型、参数校验和支付商品核验限定 USD；历史订单读取及回调快照的币种类型单独保留兼容，不能把全部历史类型一律收窄为 USD。
- 价格目录、客户端期望金额/币种、服务端报价、支付平台商品及折扣回执必须一致。保留现有幂等、报价失效、支付核验和退款逻辑；错误报价不能创建订单或发积分。
- P0 只读盘点存量订单币种和未完成订单。若存在旧非 USD 订单，保留原金额、原币种及查单、回调、退款/争议处理，不按新 USD 目录重写或重新创建支付链接；历史显示如实标注原币种，不代表继续提供该币种新充值。
- `.env.example`、支付说明、套餐组件及测试样例同步体现 USD 新充值约束；仅用于旧交易兼容的其他币种样例明确标记用途。
- 托管支付页需实际核验商品币种与支付请求为 USD；不能仅修改前端货币符号后宣称完成。本次文档修订不改变线上支付配置、价格或存量订单。

以上均为拟新增或拟调整位置，不表示文件已经存在。代码示例的注释、开发说明继续使用中文；资源中的英文属于产品翻译内容。

建议命名空间为 `common`、`navigation`、`auth`、`settings`、`dashboard`、`workstation`、`toolbox`、`canvas`、`email`、`assets`、`tasks`、`billing`、`help`、`errors`。

资源键使用业务语义，例如 `workstation.tools.relight.title`、`tasks.states.processing`、`billing.insufficientCredits`。避免将整段中文作为键，也避免不同业务含义的相同短词共用一个键。

## 5. 文案与格式规则

1. 使用完整句子和命名插值，如数量、上限、工具名称；不通过中文语序的字符串拼接生成英文句子。
2. 数量使用 i18next 的 `count` 与对应复数资源，覆盖 0、1、多项。
3. 初步术语建议：裂变为 `Image Variations`、重新打光为 `Relight`、精修为 `Retouch`、扩图为 `Outpaint`、智能抠图为 `Background Removal`；在术语表统一后应用到导航、帮助和计费说明。
4. 模型品牌、型号、文件格式、比例、分辨率和平台名称保留其正式名称。
5. 输入长度文案与当前校验单位一致；不能把原有字符长度限制翻译为英文单词数。
6. 日期和数字统一走 `src/i18n/format.ts`。英文界面可映射 `en-US` 作为格式语言，不自动改变时间戳或产品时区。
7. 相对时间处理无效日期、刚刚、分钟、小时和天；固定测试时钟验证两种语言。
8. 新价格目录和新订单固定 USD；语言只影响金额格式与说明，不改变美元金额。存量订单继续按记录中的真实币种展示，不能统一换符号或改写金额。
9. 计费月份继续按既有上海时区规则计算；展示月份可翻译，配额刷新周期不变。
10. 帮助及计费文案继续读取真实价格和额度来源，不在英文资源中复制另一套业务数值。
11. 用户提示词、邮件原文与结果、用户模板名称、水印文字、项目及图层名称不自动翻译。
12. 新建系统默认名称可在创建时使用当前语言，保存后按普通内容保留；语言切换不批量改写旧项目或历史记录。

## 6. 配置与业务逻辑解耦

### 6.1 导航、工具和帮助

- 路由 slug、能力枚举、操作标识及 `value` 保持稳定；显示名称通过资源键或展示辅助函数取得。
- `NAV_META`、`SUB_ROUTE_LABELS`、工具目录、首页快捷入口及帮助目录统一使用同一套名称来源。
- 帮助分组用稳定分组标识，翻译后的名称只用于展示，不作为分组键。
- 对 `useMemo`、`useCallback` 和模块级常量逐一检查；显示计算随语言更新，业务函数保持原依赖边界。
- 修改注册表时在同一评审单元内迁移其消费者。共享定义中仍被内部 Prompt 或旧逻辑使用的中文标签可以保留，已迁移界面通过统一展示函数取名称。
- 不一次删除所有旧 `label` 字段，避免尚未迁移模块及内部指令被连带改变；保留位置必须在清单注明用途。

### 6.2 计费说明

`billingCopy.ts` 除文本提取外，需要处理以下事项：

- `assertWorkstationToolsCovered` 改为校验工具标识与计费操作的映射关系，不比较翻译后的名称。
- 按分辨率、数量、单价、单位和降级规则等结构化数据分组，不用拼接后的说明文字作为分组依据。

- `shared/relight.ts`、`shared/retouch.ts` 等内部固定 Prompt 保持现有语言和约束。

- 历史任务优先根据已有结构化参数展示选项名称；不能可靠还原的原始摘要按历史内容保留。
- 不通过全量替换中文字符串改变 Prompt 长度预算、模型参数、历史数据或服务端错误判断。

## 7. 统一错误与警告展示契约

### 7.1 兼容现有接口

保留现有 `error`、`code`、`requestId`。有动态数值需要展示时，增加可选 `messageParams`，例如：

```json
{
  "error": "单张图片不能超过 20 MB",
  "code": "IMAGE_TOO_LARGE",
  "requestId": "原请求追踪编号",
  "messageParams": { "maxMegabytes": 20 }
}
```

- 旧客户端继续使用原 `error` 字段；新客户端按 `code + messageParams` 本地化。
- 参数使用明确白名单，只传数值、已知枚举等展示所需数据，不加入原图、提示词、邮件、令牌或供应商响应正文。
- 先补齐主要用户路径中缺失或过于通用的错误码；内部维护路径按实际需要处理，不为消除统计数字盲目改写全部错误。
- 旧错误与未知错误保持兼容。无需为了本次展示改造迁移历史任务表或改写存量 `error_message`。
- 持久化任务没有足够参数时展示当前语言的错误类别说明；保留原始诊断数据，不从中文句子中猜测金额或恢复事实。

### 7.2 客户端落点

1. 扩展 `ApiError`、`CloudError` 的可选元数据，保持现有构造方式兼容；两条请求路径均保留错误码及参数。
2. 检查绕过这两条路径的直接 `fetch`、同步计费、对象读取和上传错误，统一进入展示适配器。
3. 本地校验优先返回结构化描述，再在组件中翻译；必须抛出异常的地方保留可识别代码，避免用显示文字驱动逻辑。
4. 统一展示器按错误域、错误码、参数和上下文生成文案。未知错误使用当前语言的通用提示，并保留可用的请求追踪编号。
5. 任务中心、工作站恢复、资产、积分明细、邮件批量错误及云同步提示都应使用该展示器。
6. Supabase 登录错误优先识别 `AuthError.code`，如凭据无效、邮箱未验证；不依赖可能变化的原始英文消息。OAuth URL 错误描述作为非可信诊断内容处理，不直接拼接 HTML。
7. 现有警告码如 `RESOLUTION_DOWNGRADED_4K_UNSUPPORTED_RATIO`、`LATE_RESULT_NO_CHARGE` 按原稳定标识翻译，不能改变降级、退款或迟到结果的事实含义。
8. 服务端原错误文本可以继续用于既有诊断及内部兼容逻辑；不新增敏感内容日志或翻译上报服务。

英文环境的默认提示不能直接回退为原始中文。对没有结构化描述的旧记录，可提供英文通用说明和原请求编号；是否展示原始诊断详情需单独定义。

## 8. 批量邮件 CSV 兼容规范

### 8.1 字段与别名

| 内部字段 | 现有中文列名 | 建议英文模板列名 |
| --- | --- | --- |
| `sourceText` | 原始邮件内容 | Source email |
| `instruction` | 编写指导 | Writing instructions |
| `generationSettings` | 生成设置 | Generation settings |
| `language` | 语言 | Language |

- 模板显示列名与内部字段分离；上传解析不读取当前语言的 `t()` 输出。
- 任何界面语言均接受既有中文模板和新英文模板；英文别名规范化大小写与首尾空格。
- 中英文别名映射后检查重复字段。例如同时出现“语言”和 `Language` 应报告冲突，不能静默覆盖。
- 保留现有额外列处理方式、必需列规则、行号和空行行为，不借国际化扩大导入限制。
- 内部保存规范化字段、原始单元格内容及原 CSV 记录行号；不把显示列名作为业务对象键。

### 8.2 操作与语言取值

- 操作接受既有中文名称、约定英文名称和稳定代码，如 `reply`、`summarize`、`polish`、`grammar`。
- 润色方式接受原中文名称、英文名称及 `clear/shorten/lengthen/simplify`；继续兼容原有冒号、中文冒号和 `+` 组合方式。
- 输出语言接受原语言代码和中英文名称；历史 `en-US/en-GB` 继续按现有校验兼容。
- 空设置仍按导入时原个人默认值解析。切换界面语言不能重新解析已经导入的批次，也不能改写已确定的输出语言和型号。
- 所有别名放在固定解析字典中，不根据当前资源动态匹配，避免后续润色文案破坏旧 CSV。

### 8.3 模板、导出和队列

- 当前界面语言决定新下载模板和结果列名；原单元格及结果内容保持其原语言，继续执行已有公式注入转义。
- 表头示例优先改为可翻译的 HTML 表格；如保留 PNG，则维护双语预览并与实际模板核对。
- 保留 UTF-8 BOM、Papa Parse 处理、50 条及 5 MB 上限、逐行错误、原记录行号和结果导出语义。
- 批次继续只在当前页面会话中保留；不添加后台队列或刷新后自动重建。
- 串行执行、单个/批量共享提交锁、待确认暂停、原请求查询恢复、失败后手动重试保持原行为。
- 语言切换不重新生成请求编号，不自动重试、不继续下一条状态未知的任务。

## 10. 自动化检查和测试策略

### 10.1 拟新增的检查

在 `package.json` 中增加 `i18n:scan` 和 `i18n:check`，并复用现有 TypeScript、tsx 和 Vitest。

检查工具按职责分工，不预设自写脚本天然优于成熟插件：

| 检查方式 | 主要职责 | 边界 |
| --- | --- | --- |
| `i18n:scan` | 生成候选文本、分类清单和模块迁移覆盖面 | 定位不等于理解语义，Prompt/UI 分类需要明确规则及人工确认 |
| `i18n:check` | 校验资源语义键、插值、复数、空值及项目特有约束 | 不重复实现已由 lint 可靠覆盖的全部字面量规则 |
| ESLint 国际化规则 | 开发时提示并在 CI 拦截已迁移界面的新增硬编码 | 优先验证 `eslint-plugin-i18next`；只采用经当前配置验证的规则与例外 |

- P0 使用 JSX 文本、`placeholder/aria-label`、`message.error`、`label` 配置对象、模板插值、内部 Prompt、日志、URL/枚举及测试数据作为正反例，比较覆盖与误报；同时验证当前 ESLint 10 flat config、TypeScript 及构建链兼容性。
- 已验证的成熟规则优先复用。若关键调用点未覆盖，补充明确的项目规则；若插件无法兼容，记录原因并验证替代检查，不能只保留扫描报告而缺少 CI 拦截。
- 扫描排除注释、测试、翻译资源和已分类的内部 Prompt；例外按具体字段、常量或调用点登记用途，不整目录忽略，也不依赖“自研能自动识别 Prompt”的假设。
- UI 硬编码检查覆盖中文和英文，不仅搜索中文字符；新写的英文常量也可能破坏中英切换。
- 资源检查对应语义键及插值参数，归一化复数形态后比较资源覆盖，并按语言复数规则验证需要的形式；检查空字符串和错误的资源返回类型。
- 将必须拦截与必须放行的代表性样例纳入检查器回归，证明规则生效；例外有理由、范围和维护位置。
- 对异常描述、工具展示函数、CSV 别名及格式化编写有行为差异的测试，不为每个字面值建立重复测试。
- P0 先记录存量；各步骤只对已迁移范围逐步收紧，P6 才执行全范围门槛。

### 10.2 现有测试的处理

- 既有测试显式固定中文及原中文文案语义，隔离浏览器自动探测，优先保留既有断言；不为国际化机械重写全部 264 个文件。
- 另设首次探测测试，覆盖英文、中文、地区变体、语言列表、其他有效语种、缺失值、非法值、开关关闭、手动优先及一次性初始化，不用全局中文设置掩盖首屏行为。
- 对双语行为使用真实翻译资源，不统一 mock 为原始资源键。
- 测试前清理当前用例的语言缓存与语言状态，测试后恢复，避免串扰。
- 涉及全局应用实例的语言切换测试避免并发改写同一实例；纯函数优先注入翻译/格式参数。
- 服务端和纯共享测试不因前端 setup 引入浏览器依赖。
- 检查 Vitest 的未处理异常与异步资源清理；仅断言数量通过不代表套件有效通过。

### 10.3 重点行为矩阵

| 维度 | 必需场景 | 通过条件 |
| --- | --- | --- |
| 语言基础 | 中文/英文互切、刷新、非法缓存、存储被禁用 | 语言选择确定，无资源键泄漏 |
| 首屏探测 | `en-US/en-GB`、`zh-CN/zh-TW`、语言偏好列表、其他语种、空值及读取失败 | 未初始化时按规则选择，首次渲染正确；已有选择不被覆盖 |
| 身份边界 | 匿名、首次登录、退出、A/B 账号、不同运行分区 | 不串写选择，不影响数据身份与权限 |
| 换设备 | 当前设备曾手动选择，另一设备没有本地记录 | 新设备按自己的浏览器初始化，不宣称云端已恢复语言偏好 |
| 资源格式 | 缺失键、0/1/多项、插值、长句和无效日期 | 资源完整，提示与实际数据一致 |
| 业务保持 | 已上传文件、蒙版、草稿、表单和处理中任务时切换 | 内容和请求编号不变，额外提交次数为 0 |
| 错误路径 | Axios、cloudRequest、直接请求、本地校验、认证和历史错误 | 已知码准确、未知码有当前语言回退 |
| USD 新充值 | 中英文目录、折扣报价、创建接口、支付商品、错误币种输入及开关关闭 | 新充值全链路固定 USD；非法币种不能创建订单，语言与开关不改变币种策略 |
| 存量交易及计费保持 | 原订单、查单/回调、退款/争议、同一账本、上海月份和额度 | 按原金额和币种核验，不改写旧交易、不重复发积分，语言不影响账本 |
| 防回退 | UI 中英文硬编码、Prompt/日志例外、资源缺失、插值与复数错误 | 需要拦截的样例使 CI 失败，正确资源及已登记例外放行 |
| Prompt 保持 | 打光、精修、智能编辑、邮件参数 | 相同输入的模型请求内容不因界面语言变化 |
| CSV | 中文/英文表头、混合别名、重复字段、空默认、多行与公式内容 | 兼容原文件；参数、记录行号及安全转义正确 |
| 画布与项目 | 正在生成、编辑图层、切换项目受阻、旧名称与旧草稿 | 不重建画布、不覆盖旧内容、不绕过保护 |
| 公开内容 | 未登录直达、刷新、语言链接、SPA 回退 | 两种语言 URL 均可用 |
| 认证邮件 | 注册验证、重发、找回密码、旧账号、无语言元数据、跨设备回调及共享产品 | 真实收到完整英文内容，链接正确，操作完成；P6 前必须通过 |

已有门禁命令：

```bash
git diff --check
npm test
npm run build
npm run lint
```

实施后新增的命令，当前尚未存在：

```bash
npm run i18n:scan
npm run i18n:check
```

每个步骤先运行相关测试，再执行约定的合并门禁；通过后不重复运行没有新增风险的同一组检查。涉及真实账本存储逻辑的修改超出本轮预期，应重新评估范围及数据库验证要求。

- 新错误字段是可选字段，旧客户端继续读取原错误消息。

- 历史中文 CSV 始终可导入，新语言缓存不能改变项目或任务存储结构。
- 本轮无数据库迁移。任务恢复、结算和退款继续由原链路处理，不能通过回退国际化重放任务。

## 13. 实施起点

开始编码时先完成 P0 的清单、兼容版本、首次语言与邮件配置契约及基线检查，再提交 P1。P1 验证语言基础、登录和公共框架可用后，按 P2–P5 迁移业务模块；P5A 可在 P1 后提前进行，但必须完成并留证后才执行 P6。

本次文档不表示依赖已经安装、翻译已经完成、测试已运行、数据库已调整、代码已提交或发布。
