## 1. 交付目标和范围

最终交付应满足以下要求：

1. 中文保持默认语言；用户可在登录页和设置的“通用”页切换英文。
2. 语言切换即时更新当前页面，刷新后可以恢复选择。
3. 登录前页面、主导航、设置、首页、8 个图片工作站工具、4 个工具箱工具、自由画布、邮件助手、资产、任务中心、积分与充值均支持英文。
4. 9 篇帮助文章以及关于、隐私页面提供对应英文内容。
5. 已迁移页面没有缺失资源键、裸露翻译键或意外的中文系统提示。用户内容、品牌名称、模型名称和原始结果按原内容显示。
6. 切换语言不清空表单、上传文件、蒙版、画布草稿、选中项、批量队列或已获得的结果。
7. 切换语言不会额外提交生成、充值、重试、退款或其他业务写请求，不改变原任务编号和幂等标识。
8. 同一组业务输入在两种界面语言下产生相同的生成参数、模型选择和计费请求。

本轮保持既有积分价格、免费额度、计费周期、币种、模型策略、账号及运行环境隔离。邮件的“输出语言”仍由原邮件参数和用户偏好决定，不跟随界面语言自动变化。

首版不新增云端语言偏好字段，不修改数据库表或账本函数。跨设备同步语言、自动识别浏览器语言、其他语种、全站语言路由前缀、区域定价及模型 Prompt 的语言优化可独立立项。

第三方支付托管页、Google 授权页和 Supabase 发出的认证邮件不由本仓库页面控制。本轮验收记录其实际语言；这些外部内容若也要求统一英文，需要另列配置任务，不能以 Web 页面完成替代外部流程验收。

## 3. 先冻结的技术规则

### 3.1 国际化实例与资源

- 使用 `i18next + react-i18next`，安装时验证与现有 React 18、TypeScript 5 和构建链的兼容性，提交锁文件；不顺带升级 React、AntD 或 Vite。
- 由 i18next 实例提供当前语言，避免再建立一个独立、可能失去同步的语言状态源。
- 翻译资源按业务模块拆分，首版随应用打包，不依赖额外的翻译接口或远程资源服务。
- 固定 `supportedLngs`，对非法缓存值回退中文；默认不启用浏览器语言自动探测。
- 开发阶段允许缺失英文资源暂时回退中文；最终发布前以资源检查和页面验收消除计划范围内的缺失。
- 语义键、类型声明及调用方式在 P0 锁定。默认采用类型化语义键方案；确认所选 i18next 版本的字符串键与 selector 配置，避免依赖大版本默认值。
- 增加布尔构建开关 `VITE_I18N_ENABLED` 控制英文入口，缺省关闭；开发和预览验收时显式启用。关闭时即使缓存为英文也使用中文，中文页面仍经由相同资源层渲染。
- 在全局中文默认回归通过后再逐模块迁移；不使用运行时扫描 DOM 替换文本的方式。

### 3.2 语言选择与本地记忆

首版界面语言只保存在当前浏览器，不加入现有 `usePreferencesStore` 的云端字段补丁。

建议缓存键为 `pixel:ui-locale:v1:<origin>:<runtimeKey>:<owner>`：

- `runtimeKey` 根据现有构建模式和云模式生成，与应用已有本地缓存分区规则保持一致。
- 登录前使用匿名分区；登录后使用当前用户分区，不改变历史、任务或偏好本身的身份规则。
- 账号有保存值时使用该值；首次进入的账号可继承当前匿名会话明确选择的语言，无显式选择则使用中文。
- 用户在已登录状态下的修改只写当前账号分区，不覆盖匿名值；退出后恢复匿名选择。
- A 账号切换至 B 账号时读取 B 的选择，不能把 A 的选择自动写入 B。
- 存储不可用时仍允许当前页面切换；刷新后按可读取配置回退，不阻塞应用。
- 如处理跨标签页存储事件，只接受当前身份分区的变化。
- 现有“恢复个性化默认”保持原范围；语言选择不隐式加入其云端重置请求。

初始化先读取匿名配置；账号身份就绪后再应用当前账号的配置。账号识别不能成为登录页显示翻译资源的前置条件。

### 3.3 与业务状态的边界

- 国际化初始化放在应用入口，与 AntD 的 `ConfigProvider` 联动。
- 不以语言作为根组件、路由、画布或业务页面的 `key`，避免语言切换导致整页卸载重建。
- 语言不进入生成参数、价格版本、请求指纹、任务身份或服务端数据查询缓存键。
- 翻译函数可以成为展示计算的依赖；不能因此重新触发提交、恢复、轮询初始化或项目载入。
- 异步失败优先保存错误码和参数，由当前渲染语言展示，避免结束时显示提交时缓存的旧语言文案。
- 已结束的临时 Toast 不追溯修改；仍在页面展示的错误、任务状态和说明应随语言更新。
- `shared/` 和 `server/` 不导入 `src/i18n`、React Hook 或浏览器存储。

## 5. 文案与格式规则

1. 使用完整句子和命名插值，如数量、上限、工具名称；不通过中文语序的字符串拼接生成英文句子。
2. 数量使用 i18next 的 `count` 与对应复数资源，覆盖 0、1、多项。
3. 初步术语建议：裂变为 `Image Variations`、重新打光为 `Relight`、精修为 `Retouch`、扩图为 `Outpaint`、智能抠图为 `Background Removal`；在术语表统一后应用到导航、帮助和计费说明。
4. 模型品牌、型号、文件格式、比例、分辨率和平台名称保留其正式名称。
5. 输入长度文案与当前校验单位一致；不能把原有字符长度限制翻译为英文单词数。
6. 日期和数字统一走 `src/i18n/format.ts`。英文界面可映射 `en-US` 作为格式语言，不自动改变时间戳或产品时区。
7. 相对时间处理无效日期、刚刚、分钟、小时和天；固定测试时钟验证两种语言。
8. 金额格式始终使用订单或价格目录里的真实币种。切换英文不代表把人民币转换成美元。
9. 计费月份继续按既有上海时区规则计算；展示月份可翻译，配额刷新周期不变。
10. 帮助及计费文案继续读取真实价格和额度来源，不在英文资源中复制另一套业务数值。
11. 用户提示词、邮件原文与结果、用户模板名称、水印文字、项目及图层名称不自动翻译。
12. 新建系统默认名称可在创建时使用当前语言，保存后按普通内容保留；语言切换不批量改写旧项目或历史记录。

## 6. 配置与业务逻辑解耦

### 6.1 导航、工具和帮助

- 路由 slug、能力枚举、操作标识及 `value` 保持稳定；显示名称通过资源键或展示辅助函数取得。
- `NAV_META`、`SUB_ROUTE_LABELS`、工具目录、首页快捷入口及帮助目录统一使用同一套名称来源。
- 帮助分组用稳定分组标识，翻译后的名称只用于展示，不作为分组键。
- 对 `useMemo`、`useCallback` 和模块级常量逐一检查；显示计算随语言更新，业务函数保持原依赖边界。
- 修改注册表时在同一评审单元内迁移其消费者。共享定义中仍被内部 Prompt 或旧逻辑使用的中文标签可以保留，已迁移界面通过统一展示函数取名称。
- 不一次删除所有旧 `label` 字段，避免尚未迁移模块及内部指令被连带改变；保留位置必须在清单注明用途。

### 6.2 计费说明

`billingCopy.ts` 除文本提取外，需要处理以下事项：

- `assertWorkstationToolsCovered` 改为校验工具标识与计费操作的映射关系，不比较翻译后的名称。
- 按分辨率、数量、单价、单位和降级规则等结构化数据分组，不用拼接后的说明文字作为分组依据。
- 界面、明细和计费说明从相同的名称展示函数取文案。
- 价格、已预扣、已结算、已退还和免费次数继续使用原账本及目录结果，不在翻译层重算。
- 两种语言下对同一目录输入验证金额与额度相同，区别只在展示文案与格式。

### 6.3 模型指令及历史展示

- `shared/relight.ts`、`shared/retouch.ts` 等内部固定 Prompt 保持现有语言和约束。
- UI 控件的选项通过稳定方向/风格标识翻译，不替换请求构造器读取的指令内容。
- 历史任务优先根据已有结构化参数展示选项名称；不能可靠还原的原始摘要按历史内容保留。
- 不通过全量替换中文字符串改变 Prompt 长度预算、模型参数、历史数据或服务端错误判断。

## 7. 统一错误与警告展示契约

### 7.1 兼容现有接口

保留现有 `error`、`code`、`requestId`。有动态数值需要展示时，增加可选 `messageParams`，例如：

```json
{
  "error": "单张图片不能超过 20 MB",
  "code": "IMAGE_TOO_LARGE",
  "requestId": "原请求追踪编号",
  "messageParams": { "maxMegabytes": 20 }
}
```

- 旧客户端继续使用原 `error` 字段；新客户端按 `code + messageParams` 本地化。
- 参数使用明确白名单，只传数值、已知枚举等展示所需数据，不加入原图、提示词、邮件、令牌或供应商响应正文。
- 先补齐主要用户路径中缺失或过于通用的错误码；内部维护路径按实际需要处理，不为消除统计数字盲目改写全部错误。
- 旧错误与未知错误保持兼容。无需为了本次展示改造迁移历史任务表或改写存量 `error_message`。
- 持久化任务没有足够参数时展示当前语言的错误类别说明；保留原始诊断数据，不从中文句子中猜测金额或恢复事实。

### 7.2 客户端落点

1. 扩展 `ApiError`、`CloudError` 的可选元数据，保持现有构造方式兼容；两条请求路径均保留错误码及参数。
2. 检查绕过这两条路径的直接 `fetch`、同步计费、对象读取和上传错误，统一进入展示适配器。
3. 本地校验优先返回结构化描述，再在组件中翻译；必须抛出异常的地方保留可识别代码，避免用显示文字驱动逻辑。
4. 统一展示器按错误域、错误码、参数和上下文生成文案。未知错误使用当前语言的通用提示，并保留可用的请求追踪编号。
5. 任务中心、工作站恢复、资产、积分明细、邮件批量错误及云同步提示都应使用该展示器。
6. Supabase 登录错误优先识别 `AuthError.code`，如凭据无效、邮箱未验证；不依赖可能变化的原始英文消息。OAuth URL 错误描述作为非可信诊断内容处理，不直接拼接 HTML。
7. 现有警告码如 `RESOLUTION_DOWNGRADED_4K_UNSUPPORTED_RATIO`、`LATE_RESULT_NO_CHARGE` 按原稳定标识翻译，不能改变降级、退款或迟到结果的事实含义。
8. 服务端原错误文本可以继续用于既有诊断及内部兼容逻辑；不新增敏感内容日志或翻译上报服务。

英文环境的默认提示不能直接回退为原始中文。对没有结构化描述的旧记录，可提供英文通用说明和原请求编号；是否展示原始诊断详情需单独定义。

## 8. 批量邮件 CSV 兼容规范

### 8.1 字段与别名

| 内部字段 | 现有中文列名 | 建议英文模板列名 |
| --- | --- | --- |
| `sourceText` | 原始邮件内容 | Source email |
| `instruction` | 编写指导 | Writing instructions |
| `generationSettings` | 生成设置 | Generation settings |
| `language` | 语言 | Language |

- 模板显示列名与内部字段分离；上传解析不读取当前语言的 `t()` 输出。
- 任何界面语言均接受既有中文模板和新英文模板；英文别名规范化大小写与首尾空格。
- 中英文别名映射后检查重复字段。例如同时出现“语言”和 `Language` 应报告冲突，不能静默覆盖。
- 保留现有额外列处理方式、必需列规则、行号和空行行为，不借国际化扩大导入限制。
- 内部保存规范化字段、原始单元格内容及原 CSV 记录行号；不把显示列名作为业务对象键。

### 8.2 操作与语言取值

- 操作接受既有中文名称、约定英文名称和稳定代码，如 `reply`、`summarize`、`polish`、`grammar`。
- 润色方式接受原中文名称、英文名称及 `clear/shorten/lengthen/simplify`；继续兼容原有冒号、中文冒号和 `+` 组合方式。
- 输出语言接受原语言代码和中英文名称；历史 `en-US/en-GB` 继续按现有校验兼容。
- 空设置仍按导入时原个人默认值解析。切换界面语言不能重新解析已经导入的批次，也不能改写已确定的输出语言和型号。
- 所有别名放在固定解析字典中，不根据当前资源动态匹配，避免后续润色文案破坏旧 CSV。

### 8.3 模板、导出和队列

- 当前界面语言决定新下载模板和结果列名；原单元格及结果内容保持其原语言，继续执行已有公式注入转义。
- 表头示例优先改为可翻译的 HTML 表格；如保留 PNG，则维护双语预览并与实际模板核对。
- 保留 UTF-8 BOM、Papa Parse 处理、50 条及 5 MB 上限、逐行错误、原记录行号和结果导出语义。
- 批次继续只在当前页面会话中保留；不添加后台队列或刷新后自动重建。
- 串行执行、单个/批量共享提交锁、待确认暂停、原请求查询恢复、失败后手动重试保持原行为。
- 语言切换不重新生成请求编号，不自动重试、不继续下一条状态未知的任务。
