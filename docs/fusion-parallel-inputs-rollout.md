# 融合双图并行上传：上线与验收

## 1. 本次范围

图片工作站的融合工具同时准备商品图和场景图：各自读取、识别实际图片格式、申请上传地址、直传 R2。两张图都就绪后才创建生成任务，任务请求只带对应角色的对象键。图片原始字节、输入尺寸、输出分辨率设置、模型选择和计费逻辑保持现有行为。

复用现有 `/api/task-inputs`、`/api/tasks` 和共享结果读取链路。无需 Supabase 数据库迁移、IndexedDB 升级、环境变量变更或新的 R2 配置。预览域名仍需满足现有 R2 CORS 配置。

## 2. 准备、复用与恢复

### 两个独立槽位

- 固定并发为两张图，不依赖完成顺序：商品键始终填 `sourceImageKey`，场景键始终填 `referenceImageKey`。
- 已有对象键直接复用；缺少对象键时，读取当前图片 Blob 后上传。不会为并行上传重新压缩、缩放图片。
- 按图片真实字节识别 JPEG、PNG 或 WebP；空文件、无法识别格式、超过 20 MiB 的文件在申请上传地址前拒绝。
- 每张图从读取开始限制 120 秒，覆盖读取、校验、签名、PUT；签名接口继续使用现有 API 客户端的 15 秒超时。
- R2 PUT 只携带图片内容类型，`credentials: omit`，不附加本站令牌。

### 成功图复用

- 只缓存当前商品、场景两个槽位的成功对象键，不持久化、不把临时键写回素材注册表。
- 成功上传后有效 30 分钟。缓存匹配账号、素材 ID、图片 URL、MIME、尺寸及已有对象键。
- 相同图片再次生成或修改提示词、数量、分辨率、模型时，在有效期内复用成功键。
- 更换单张图只失效对应槽位；换账号或页面卸载清除缓存。刷新页面重新开始准备。
- 账号权限、对象存在性和签名有效性继续由服务端处理；本地缓存不替代服务端鉴权。

### 一张失败时的行为

1. 立即在对应槽位显示读取、签名或上传错误；另一张继续完成。
2. 在两张都结束前，“重试失败图片并提交”不可点击，期间仍可取消准备。
3. 两张结束后，保留原提示词、数量、分辨率、模型及素材快照。点击重试只补传缺失或已过期的图片，复用仍有效的成功图。
4. 也可选择修改参数或替换图片，此时清除失败快照，保留仍匹配当前素材的成功键。
5. 输入准备失败不调用生成接口。只有用户主动重试并且两张就绪后才提交任务。

生成接口本身失败使用已有任务提交错误界面，不显示输入重试入口，也不自动再次生成。提交接口返回前的网络错误不等于服务端没有创建任务，本次不自动重发该请求。

### 取消与异步隔离

- “取消准备”只在输入准备期间显示；开始 POST 生成任务后隐藏。
- 取消、换图、换工具、换账号、卸载都会使旧准备版本失效并中止可取消的请求。
- 成功图可以在同账号后续准备中继续复用。取消不表示已发送的字节能够收回，也不立即删除已上传的临时对象；沿用现有临时对象清理策略。
- 已进入任务提交后的迟到响应不能写入新账号或新页面状态，也不能注册到当前编辑项目。已创建的云端任务不因页面切换而撤销。
- 本地选图的读取也按账号、槽位和选择版本隔离，旧文件的迟到响应不会覆盖新文件。选择成功文案为“已载入”，实际 R2 上传发生在生成准备阶段。

## 3. 观测口径

浏览器控制台使用 `[融合输入]`，每轮包含随机准备 ID，不记录图片 URL、Data URL、签名地址或令牌。

| 字段 | 含义 |
| --- | --- |
| `role` | 商品或场景 |
| `source` | 已有对象、槽位缓存、上传 |
| `readMs` / `validateMs` / `signMs` / `uploadMs` | 各阶段耗时 |
| `elapsedMs` | 本图结束时或整轮结束时的累计耗时 |
| `inputBytes` | 读取到的输入 Blob 大小 |
| `uploadedBytes` | PUT 确认成功的图片字节数 |
| `outcome` | 成功、失败或取消 |
| `overlapMs` | 两次 PUT 等待区间的重叠时间 |
| `putAttempts` | 本轮进入 PUT 的次数；缓存或已有对象不计入 |

`uploadedBytes` 不是网络层实际发送量：失败或取消时可能已经发送部分甚至全部图片，不能将其零值解释为零流量。实际 PUT 次数、传输量和时序应结合网络面板或测试服务接收记录查看。并行通常减少两张输入的串行等待，实际收益受用户带宽和 R2 链路影响，不改变模型推理时间。

## 4. 已执行验证

### 自动验证

- `npm test`：115 个测试文件、602 项测试通过。
- `npm run build`：包含服务端和前端 TypeScript 检查及 Vite 构建。
- `npm run lint`：零警告门禁。
- `git diff --check`。

新增测试覆盖双图 PUT 同时启动、逆序完成、读取与签名失败、单图失败另一图继续、仅重试缺失图、已有对象和混合输入、缓存过期、更换单图、取消、120 秒总超时、账号切换、本地选择迟到、任务创建迟到、重复点击及任务接口失败不自动重提。保留工作站、共享结果读取、历史保存等全量回归测试。

### 真实浏览器与本地测试接口

使用独立浏览器会话、本地开发站点和可控 HTTP 测试接口，未调用真实模型或生产账号。两张输入都是 3200×5035 的 JPEG，商品 7,165,557 字节，场景 7,166,118 字节。

| 场景 | 观察结果 |
| --- | --- |
| 正常并行 | 两次 PUT 启动间隔 6 毫秒；商品等待约 1508 毫秒、场景约 1209 毫秒，场景先完成，两个角色保持正确 |
| 两张就绪后提交 | 两次 PUT 都确认成功后才 POST；任务没有内联图片，商品键、场景键正确 |
| 相同双图再次生成 | 新建一轮任务，新增签名及 PUT 均为零，复用上一轮成功键 |
| 场景上传失败 | 场景返回 500 后商品继续；商品结束前重试按钮禁用，失败轮没有创建任务 |
| 重试失败场景 | 只增加一次场景签名和 PUT，复用成功商品键，随后只创建一次任务 |
| 取消双图准备 | 两条等待中的 PUT 都关闭，任务数没有增加，页面恢复可操作 |
| 结果读取与历史 | 三次成功生成各读取一次结果，页面展示和完整本地历史保存正常 |

浏览器验收曾发现开发热更新保留旧准备实例时，错误构造器身份变化会丢失输入重试状态。已改为按错误契约识别，并重新验证失败及重试流程。正常、失败、取消场景未发现应用脚本异常；人工制造的 HTTP 500 属于预期网络错误。

以上时序来自本地可控延迟，证明请求并发与恢复行为，不代表生产提速比例。真实 R2 签名、正式账号权限、预览域名 CORS、模型质量及积分需要在 PR 预览环境继续验收。

- [ ] 场景先完成、商品先完成各验证一次，确认商品内容和场景角色正确。
- [ ] 同图再次生成及修改参数后生成：30 分钟内不新增上传；每次用户主动生成仍独立创建任务并按现有规则计费。
- [ ] 更换商品、只换场景：只上传更换项。已有云端对象输入不重复上传。
- [ ] 分别让读取、签名、PUT 失败：另一张继续；结束后仅重试失败项；输入失败及取消不新增任务、不产生生成扣费。
- [ ] 准备期间取消、切换工具和切换账号：迟到图片及任务响应不覆盖当前界面和编辑项目。
- [ ] 模拟超过 120 秒，确认明确超时、成功项可复用；任务提交阶段没有“取消准备”或输入重试按钮。
- [ ] PNG、JPEG、WebP 文件声明与字节格式不一致时仍按真实格式签名；空文件、无效文件及超过 20 MiB 文件拒绝。
- [ ] 融合结果、尺寸、模型参数、积分、结果下载、本地历史保存，以及其他单图工具无回归。
