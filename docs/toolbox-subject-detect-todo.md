# 待办：智能裁剪的主体检测

> 转比例 M4。焦点换算已落地。真实检测先用数据万象图像主体检测 `ci-process=AIObjectDetect`，与商品抠图共用四项 `TENCENT_COS_*`。多个主体取面积最大的框，面积相同则取更靠近画面中心的框。主体检测没有框时，再用商品抠图的不透明区域定位。仍然没有框，或检测失败时，退回当前九宫格，不整批失败。模拟模式仍用固定框，不调用腾讯云。

## 前端已经能接什么

智能裁剪用原图上的焦点 `fx`、`fy`（0 到 1）。`0` 贴起始边，`1` 贴结束边，`0.5` 是中心。九宫格是整批共用的默认焦点。

检测接口只需返回商品主体框。框的中心由前端换算成这一张图自己的焦点。检测失败时，这张图退回当前九宫格焦点，不整批失败。

## 建议接口

同步接口，不进生成任务队列。和智能选区一样，只返回几何，不生成新图。

```ts
{ box: { x: number; y: number; width: number; height: number } | null }
```

四个数都是相对原图宽高的 0 到 1。没有主体时 `box` 为 `null`。

## 真实检测

- `POST /api/subject-detect` 接收已按显示方向编码的 JPEG，以及这张 JPEG 的宽高。长边超过 1280 时先缩小再上传，返回的框仍是相对坐标，裁剪按原图计算。一批同时最多识别 3 张。处理时卡片和页脚会写明正在识别哪一张
- 服务端把图临时放到 `subject-detect/`，先请求 `AIObjectDetect`。没有框时再请求 `GoodsMatting`（`center-layout=0`），用不透明像素的外接框作为主体框。返回相对原图 0 到 1 的框，然后删除临时对象
- 多个主体先比面积，面积相同再比谁更靠近画面中心。只把这一个框交给 `focusFromSubjectBox`
- 不进入 `createTask`。模拟模式不调用腾讯云。页面上的「模拟未找到主体」开关已去掉

## 现在可开发的步骤

下面这些步骤已经写进代码。这一期只动智能裁剪。留白填充和智能扩展不检测、不改结果。九宫格的 `fx`、`fy` 仍是整批默认值，继续记在现有偏好里。每张图自己的焦点只留在当次队列里，不写入 IndexedDB。

模拟检测不上传图片，不调用腾讯云，也不提交生成任务。它用来先看清两件事：找到主体时裁切会离开九宫格；找不到时这张图仍按当前九宫格裁完，整批不中断。

**步骤**

1. 新增纯函数 `focusFromSubjectBox(box, sourceWidth, sourceHeight, targetWidth, targetHeight)`。框的四个数都是相对原图的 0 到 1。先取框中心，再把它放进现有 `coverCrop` 的裁切窗口。某一边没有溢出时，该方向焦点保持 `0.5`。框含非数字、宽高小于等于 0，或任一坐标超出 0 到 1 时，函数返回 `null`。
2. 检测结果固定为 `{ box: { x, y, width, height } | null }`。`detectSubject(image)` 现在只调用模拟实现。以后替换这个函数即可。
3. 模拟框固定为 `{ x: 0.2, y: 0.05, width: 0.6, height: 0.45 }`，主体偏上。只在模拟模式使用。真实模式改为调用 `POST /api/subject-detect`，页面上的「模拟未找到主体」开关已删除。
4. `BatchImage` 增加本次裁切焦点：`cropFocus?: { fx: number; fy: number; source: 'subject' | 'grid'; note: string }`。改平台、策略或九宫格时，现有的 `invalidateBatch` 连同输出一起清掉它。
5. 只有策略是 `crop` 且原图和目标比例不一致时才检测。比例已经一致时跳过检测，结果仍是整图缩放。留白和扩图的处理函数不调用检测。
6. 处理一张图时：有合法框就用换算出的焦点，并记下「已按主体裁剪」。框为 `null` 时用当前九宫格，记下「没识别到商品，已按九宫格裁剪」，并提示改焦点后再处理。检测抛错也退回九宫格，记下「主体检测失败，已按九宫格裁剪」。这三种情况只要编码成功，状态都是 `succeeded`。编码失败仍走现有的整项失败。队列里的兜底说明用警告色，页脚同时标出有多少张没按商品裁。
7. 队列卡片增加可选说明 `note`。上面三句用说明样式显示，不占用失败项的红色错误。
8. 还没处理的预览继续用九宫格。这张图已经有 `cropFocus` 时，预览和下载使用同一组焦点。

换算例子：原图 `1000×1000`，目标 `1000×500`，窗口高是 500，只有垂直方向有 500 像素溢出。模拟框中心在 `(500, 275)`，所以 `fx` 保持 `0.5`，`fy` 为 `0.05`。
