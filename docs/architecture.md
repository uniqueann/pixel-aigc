## 2. 前端技术栈

- 框架：React + TypeScript + Vite
- 路由：react-router-dom
- UI 组件库：**Ant Design**
- 画布交互：fabric.js（消除/重绘的蒙版涂抹依赖）
- 状态管理：Zustand（本地状态）+ TanStack Query（服务端状态/任务轮询）
- 请求层：axios，统一走 `/api` 网关

### UI 组件库选型：为什么是 Ant Design 而不是 shadcn

两者都能用，选择 antd 是基于产品形态判断，不是随手默认：

- 本产品是**参数密集的 B 端工作台**（右侧参数面板一堆 Select/Slider、批量上传网格、任务列表），不是强调品牌差异化的营销页面，信息密度和开发效率优先于视觉独特性
- antd 的 Upload/Form/Table 开箱即用批量上传进度、表单联动校验、排序筛选；shadcn 本质是"Radix 原语 + Tailwind 抄进代码"，这类重逻辑组件需要自己拼装 react-dropzone、tanstack-table 等
- 核心交互（蒙版涂抹、拖拽扩展框）本来就要用 fabric.js 手写，不依赖组件库现成能力，shadcn "深度定制"的优势在这里打了折扣
- 折中方案：保留 antd 处理表单/表格类组件，通过 `ConfigProvider` 的 theme token 做视觉重定义（脚手架里已把主色换成墨绿而非 antd 默认蓝），成本远低于换整个组件库

如果后续产品方向转为强调营销/品牌页面（落地页、定价页），可以再评估引入 shadcn + Tailwind 做那部分。

## 3. 异步任务系统

图片/视频生成都是耗时操作，整体链路：

```
前端提交任务 → API/BFF（校验+预扣积分+写库） → 任务队列（Redis+BullMQ）
→ Worker 集群（调用 AI 模型） → 结果落地（对象存储+更新状态） → 实时推送（WebSocket/SSE）
```

关键设计点：

- **任务状态机**：`pending → queued → processing → succeeded/failed/cancelled`，失败重试次数上限后退还积分
- **幂等性**：前端提交任务携带 `requestId`，后端据此去重，避免网络重试导致重复扣费
- **积分预扣 + 结算**：提交时预扣，成功确认扣除，失败/取消退还，防止刷任务占用资源
- **限流与优先级**：按用户等级设置并发上限和队列优先级
- **数据模型雏形**：`tasks` 表（id, user_id, capability, params, status, result_url, credits_cost, retry_count, created_at, updated_at）；图片类任务关联 `image_versions` 表做版本树

## 4. Provider 抽象层

多个 AI 模型服务商（自研模型、通义万相、Midjourney API 等）需要统一接口，Worker 不直接依赖具体某家服务商：

```typescript
interface AIProvider {
  name: string
  capabilities: Capability[]
  supports(cap: Capability): boolean
  estimateCost(cap: Capability, params: GenerationParams): number
  generate(cap: Capability, params: GenerationParams): Promise<ProviderResult>
  pollStatus?(providerTaskId: string): Promise<ProviderResult> // 异步provider需要
}
```

- 能力矩阵（provider × capability）做成可配置数据，后台可增删 provider 不用发版
- 主 provider 失败时自动降级到下一候选（按成本/成功率/负载打分排序）
- 降级要考虑幂等，避免主备双跑导致重复扣费
- 前端只通过统一的 `/tasks` 接口提交参数，永远不直连某个模型服务商

## 5. 图片工作站交互模式

```
┌─────────────────────────────────────┐
│ 左：工具切换栏 │ 中：画布区 │ 右：参数面板 │
├─────────────────────────────────────┤
│           底部：历史版本 + 生成按钮        │
└─────────────────────────────────────┘
```

8 个功能归纳为 5 种画布交互模式：

| 交互模式 | 适用功能 | 说明 |
|---|---|---|
| 纯参数型 | 智能编辑、裂变、精修 | 不需要画布操作，右侧选参数直接生成 |
| 蒙版涂抹型 | 消除、重绘 | 需画笔工具条：笔刷大小、橡皮擦、智能选区、撤销重做；重绘额外需要文本描述框 |
| 拖拽调整型 | 扩图 | 画布显示原图+可拖拽扩展边框，或直接选平台预设比例 |
| 多图合成型 | 融合 | 右侧变为多图上传区，可能需要框选融合位置 |
| 光源控制型 | 打光 | 预设模式卡片（强光/柔光）或手动方向盘+强度滑块，画布实时预览光影 |

底部历史版本区保留每次生成结果，支持回退到任意历史版本继续编辑，而非简单覆盖。

## 6. 工具箱模块设计

三个工具共用批量处理骨架，参数区差异：

- **智能抠图**：参数最少（输出背景：透明/白底/纯色），批量完成后支持对个别图片做边缘精修（复用消除/重绘的蒙版工具）
- **加水印**：水印类型（文字/Logo）、位置、透明度、大小，设置一次应用到全部，建议先出单张预览
- **转比例**：支持多选目标平台一次生成多个平台版本，适配策略需覆盖智能裁剪 / 智能扩展（复用扩图能力）/ 留白填充

智能抠图、转比例（智能扩展模式）复用图片工作站的抠图/扩图 Capability，不需要重复接入模型。

## 9. 视觉主题：暗色创作工具风

整体主题方向定为暗色（对标 Lightroom/Figma 的创作工具风格），理由：图片处理场景长时间盯图不易疲劳，深色背景也让照片色彩更容易判断。核心原则是不用纯黑纯白，靠背景明度分层做视觉层次；主色沿用此前定的墨绿色系，但提亮以在深色背景上保持足够对比度。

| Token | 值 | 用途 |
|---|---|---|
| `--color-bg` | `#17171a` | App 最底层背景 |
| `--color-surface` | `#1f1f23` | 卡片/面板背景 |
| `--color-surface-2` | `#29292e` | 面板内嵌套元素背景 |
| `--color-canvas` | `#3a3a3e` | **画布专用**，不与面板共用背景色 |
| `--color-border` / `--color-border-strong` | `#38383e` / `#4a4a52` | 边框 |
| `--color-text-primary` | `#ededec` | 主要文字（非纯白，避免眩光） |
| `--color-text-secondary` | `#9c9a9f` | 次要文字 |
| `--color-text-muted` | `#6c6a70` | 弱化文字 |
| `--color-accent` | `#21cfa0` | 主色（提亮版墨绿，用于按钮/选中态） |
| `--color-success` / `--color-warning` / `--color-danger` | `#4ade80` / `#f5b942` / `#f2685c` | 任务状态语义色 |

**画布专用色的原因**：专业修图工具从不用纯白/面板色做画布背景，因为周围颜色会干扰人眼对图片真实色彩的判断。这个工具的核心场景是电商产品图，色彩准确性直接影响用户对生成效果的判断，所以 `--color-canvas` 单独定义，明度介于面板背景和边框之间，不跟随主题切换算法自动生成。

**实现方式**：antd 侧启用 `theme.darkAlgorithm` 并覆盖 `colorPrimary/colorBgContainer/colorBgLayout` 等 token 与自定义色板对齐；自定义 CSS 变量集中在 `src/styles/global.css`，各页面统一引用变量而非写死颜色值，后续如果要支持亮暗切换，只需要维护两套 token 并让 `ConfigProvider` 的 `algorithm` 和 CSS 变量随切换状态联动。

## 10. UI 框架完善（导航、面包屑、通用组件）

**路由改为承载子工具/子模式状态**：图片工作站、工具箱、自由画布内部原来是组件内 `useState` 切换 Tab，刷新会丢状态、也没法生成准确面包屑。现在改为嵌套路由 `/image-workstation/:tool`、`/toolbox/:tool`、`/canvas/:mode`，每个子工具/子模式有自己的 slug（定义在各页面的 `tools.ts`/`modes.ts` 里），进入一级路径时通过 index route 重定向到默认子项。好处：可以直接分享/收藏某个具体工具的链接，浏览器前进后退在子工具间也能正常工作。

**面包屑与页面标题**：`router/meta.ts` 聚合各页面的 slug→标签映射，`MainLayout` 据此渲染面包屑，并同步更新 `document.title`（如「消除 · 图片工作站 · AIGC 工作台」）。新增子工具/子模式时只需要改对应页面自己的配置文件，面包屑会自动跟上，不用手动维护第二份映射。

**侧边栏折叠**：`Layout.Sider` 用 `collapsible` + 自定义 `trigger`（放在 Header 里的折叠图标），折叠后菜单退化为纯图标模式。

**Header 补全**：左侧折叠按钮 + 面包屑；右侧积分余额（读 `useUserStore`，待接入真实接口）+ 用户头像下拉（设置/退出登录占位）。

**全局通用组件**：
- `components/EmptyState.tsx`：统一空状态展示，已用在"我的资产"
- `components/ErrorBoundary.tsx`：包裹在 `Content` 区域外层，单个页面渲染报错时只有内容区变成错误提示，导航栏依然可用
- `main.tsx` 引入 antd v5 的 `App` 组件包裹根节点，让 `message`/`notification` 能正确跟随 `ConfigProvider` 的暗色主题
- `useTaskPolling` 接入 `notification`，任务从进行中变为成功/失败时全局提示一次
