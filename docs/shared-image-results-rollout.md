# 共享结果读取与本地历史上线说明

## 范围与使用行为

- 工作站智能编辑、裂变、精修、融合、重新打光的异步结果，以及消除、重绘、扩图的同步结果接入共享读取。
- 公共大图预览、对比预览、下载、我的资产补记，以及工具箱抠图和转比例现有的结果读取复用该链路。
- 小结果仍可直接返回 Blob；对象结果由浏览器直读 R2。结果展示、保存和下载复用 Blob，不自动回退服务器二进制代理。
- 当前账号在当前浏览器保留最近 50 张完整图片。在线刷新后读取本地历史；页面已打开时，断网仍可下载已保存的图片。
- 本次没有实现断网刷新或离线启动站点，账号初始化仍需要网络。

## 读取链路与限额

`已有 Blob → 当前账号内存缓存 → 当前账号 IndexedDB → 签名地址 → R2`

- 按账号和对象键合并进行中的请求；单个使用方取消不影响其他使用方，全部取消或账号切换时中止底层请求。
- 共享缓存最多 32 项。普通设备 128 MiB，粗指针设备 64 MiB；超过预算的单图由当前视图持有。
- 全局最多两个远程图片下载，出队时检查签名。剩余不足 30 秒重新签名；403 或网络异常最多刷新并重试一次。
- 每次图片下载的 60 秒限时覆盖响应头和正文。取消不自动重试，可读 404 提示对象不存在；跨域异常不能用于判断对象被删除。
- R2 请求使用 `credentials: omit`，不携带本站令牌；签名接口使用 `private, no-store`，客户端也禁止缓存签名响应。
- 共享层根据文件头识别真实 MIME；各使用方独立检查期望格式，工作站继续解码校验尺寸，抠图继续校验 PNG 和原图尺寸。失败的图片校验会使共享缓存失效。
- Blob URL 由使用方持有租约。结果等待 React 视图认领期间保留；当前结果、原图和画布仍引用时保留；最后一个使用方释放后撤销。对比预览也使用已经取得的本地地址。
- 项目中的结果引用保留对象身份和可恢复地址，运行时地址不回写到持久化素材。

## 历史结构与身份

IndexedDB `pixel-aigc-history-v2` 的结构版本由 1 升为 2：

| 存储 | 用途 |
| --- | --- |
| `workstationResults` | 完整 Blob；旧 ArrayBuffer 保持可读 |
| `metadata` | 账号、稳定身份、工具说明、尺寸和时间 |
| `thumbnails` | 最长边 320 像素的 PNG |
| `deletedResults` | 当前账号主动删除的结果标记 |

- 原图、元数据与 50 条保留策略在同一事务中提交，失败时回滚并保留原历史。
- 列表只读取元数据和缩略图，放大、下载时读取对应原图；保存和淘汰不会用 `getAll` 载入所有原图。
- 缩略图在后台单并发处理，已知尺寸时在解码阶段就限制尺寸。旧库升级逐条建立元数据，缩略图可在下次打开时继续生成；生成失败用占位图，完整原图仍可下载。
- `resultImages` 增加可选 `ordinal` 和 `expiresAt`，无需数据库字段迁移。序号来自已有的任务子项，过滤失败项、追加晚到项都不会改变结果身份。
- 新身份使用 `任务ID:o序号`，与旧数组位置 ID 分开。同一对象已有明确关联时保留旧资产/历史 ID。
- 旧历史只有任务版本一致且数组位置可确认时补齐对象键；无法确认时保留旧记录并跳过该任务的自动重建。
- 补记先合并并去重任务，分页读取元数据；详情最多四个并发。先在本地和云端候选中选择最近 50 张，再下载缺失项；单张失败不会触发更旧候选下载。
- 主动删除写入删除标记，正常淘汰不写标记。相同对象即使换了历史 ID，也不能因后台补记重新出现。
- 多标签页共享已提交的历史；同一请求去重保证限定在同一应用页面会话。

## 失败与恢复

- 生成状态、读取状态、图片可用状态、本地保存状态分别显示。
- 生成成功后保留结果描述。工作站支持逐张展示和保存；部分失败时只需重试读取已有结果。
- 同步对象结果下载失败后保留恢复信息；“重试读取”不调用生成接口。内联正文中断且没有对象描述时，提示用户主动重新生成。
- 历史保存失败显示“历史未保存”，当前图片仍可下载；“重试保存”复用同一 Blob。空间不足提示明确显示存储问题。
- 我的资产显示补记失败提示，提供重试历史读取与保存；失败不会清空已有图片。
- 任务版本去重与成功应用分别记录。账号、当前操作和任务版本隔离迟到响应；准备原图时切换账号，也不会向新账号提交旧请求。

## 本地验证证据（2026-10-01 至 2026-10-02）

回归覆盖共享请求、缓存淘汰和预算、取消、账号隔离、签名刷新、404、正文超时、真实 MIME、稳定身份、跨页选择、部分失败、删除标记、空间不足回滚、旧库中断恢复、多标签页升级阻塞、运行时地址认领/释放，以及读取和保存重试不重新生成。

### 真实 Chromium 验证

使用独立浏览器会话和本地跨域 HTTP 图片服务模拟 R2，不使用线上账号或消耗生成积分。

| 检查 | 观察结果 |
| --- | --- |
| 四个使用方并发读取同一 JPEG | 同一 Blob，远程图片 GET 1 次，7,165,557 字节 |
| 保存、预览和重复下载 | 图片 GET 仍为 1 次；请求未携带鉴权头 |
| 在线刷新后读取历史 | 50 条历史恢复；没有新增远程图片 GET |
| 已打开页面断网后下载 | 本地读取 7,165,557 字节，重复下载成功，实际扩展名为 `.jpg` |
| PNG 完整性 | 40×30 PNG，测试像素 Alpha 为 102；下载文件名修正为 `.png` |
| 50 张不同的大图历史 | 每张 3200×5035、7,165,562 字节；50 个不同 JPEG 文件，列表原图读取 0 次，50 张缩略图最长边均为 320 |
| 内存观察 | 当前页 JS 堆约 35 MiB；同一 Chrome 进程树 RSS 从约 1,200 MiB 到 1,365 MiB，增加约 165 MiB |

内存数据是本次测试设备上的观察值，包含 Chrome 的其他渲染进程、GPU 和导航缓存；缓存预算只限制共享 Blob 缓存，不能当作浏览器总内存上限。大图预览和画布还需要解码后的像素内存。

### PR 预览环境验收

本地测试验证了浏览器行为、跨域读取和存储，真实 R2 的签名、权限和 CORS 需在预览环境验收：

1. 单张与四张生成各跑一轮，网络面板只统计实际 R2 图片 GET，正常每个结果首次 1 次。
2. 预览、对比、保存、重复下载后，GET 和完成下载的字节数不增加。
3. 在线刷新我的资产，再断网下载；不得新增 R2 图片请求。
4. 验证签名过期、部分下载失败和保存空间不足。读取重试不得调用 `/tasks`、`/erase`、`/repaint`、`/outpaint`。
5. 在另一个标签页查看同一历史；删除后刷新与补记都不能复活。
6. 用透明大 PNG、连续编辑和多轮扩图检查 Alpha、尺寸、真实格式、扩展名及地址释放。

## 观测与上线

- 客户端记录读取来源、每次实际图片请求、成功读取字节、排队耗时、签名刷新耗时和历史保存耗时。
- 失败或中断请求的已传输字节不一定可由浏览器可靠取得，不能把成功下载字节当作失败请求的全部传输量。可结合 R2/网络面板统计。
- 不记录签名地址、鉴权头或令牌。主要优化证据为图片 GET 数和传输字节，不将生成模型本身耗时记为下载收益。
- 无需 Supabase 数据库迁移，也无需新增 R2 权限。IndexedDB 在首次打开时自动升级；旧标签阻塞升级会提示关闭后重试。

## 回退兼容性（必须遵守）

直接回退完整的版本 1 前端不可行：它硬编码打开 IndexedDB 版本 1，遇到版本 2 会报 `VersionError`，也不能读取新增 Blob 字段。旧原图数据没有删除，但旧读取代码不能直接访问升级后的库。

**回退产品改动时必须保留本 PR 的 `src/features/assets/workstationHistory.ts`。** 该模块保留旧调用需要的 `listWorkstationHistory`、`recordWorkstationHistory`、删除和清空接口，并同时读取 Blob 与旧 ArrayBuffer；旧资产页面通过它仍能读取完整图片。其他文件可以随回退版本恢复。

操作流程：在回退分支保留/恢复本 PR 的历史模块，执行完整测试与构建后部署；禁止清空 IndexedDB 或降级数据库结构。未来发布的回退基线也必须包含此兼容读取模块。
